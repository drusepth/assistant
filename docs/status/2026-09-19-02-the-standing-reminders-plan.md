**The standing reminders plan**: "remind me every Thursday night to take the trash out" turned out to be a shape the app couldn't hold — D-reminders fires once, events flatten recurrence on import by design, tasks are done or not done, and the honest answer to the question was fifty-two one-shot reminders or a hand-written `.ics`. `docs/REMINDERS_PLAN.md` is the plan and D-standing-reminders the decision. The shape: recurrence lives on the **Reminder**, not on Event (calendar recurrence is the tarpit the importer already declined) and not on Task (the tempting one — a respawning task fights the done/not-done invariant and the staleness markers the Tasks page built to defuse the graveyard; that larger question is logged open as Q-routines, and a Task can carry a standing reminder today without any of it). `deliver_at` keeps meaning one absolute indexed moment — now the *next* one — and the dispatcher advances it in the same conditional `update_all` that claims the row, so there is no window between sent and re-armed. Missed occurrences are skipped, never delivered late: a box off for three Thursdays sends nothing about them and the series survives. The rule is `RRULE` text, because `Events::Import::Ics` already parses and expands that subset with DST-safe arithmetic — W1 extracts it into `Recurrence::Rule`, one grammar tested once, and the picker composes explicit rules so the next occurrence needs no anchor column. The UI is one **Repeat** select (the Google Calendar list) beside the date and time on the two forms that already exist. Three waves, each green on its own; nothing built yet.
