**The app is installable: the PWA manifest is routed, complete, and tested**: everything PWA-shaped in the repo was still Rails scaffold — `manifest.json.erb` carrying `"theme_color": "red"`, a red-circle placeholder icon, a commented-out service-worker stub — and, the part that made the rest moot, no route pointing at any of it and no `<link rel="manifest">` in the layout. It is wired up now, and three things had to be true for it to work. The manifest needs a **pinned format**: Rails' own `PwaController` renders `pwa/manifest` in whatever format the request negotiated, and a browser fetches a manifest with `Accept: */*`, which Rails resolves to `:html` — so the JSON template is never found and the scaffold route, uncommented as-is, 500s. `application/manifest+json` is now registered as `:webmanifest`, the template renamed to match, and the route pins `defaults: { format: :webmanifest }` — which fixes the lookup and gets the spec's media type for free. The **icons are generated**: `public/icon.svg` is the source (the terracotta dot on canvas cream that the header, the rail, and the sign-in page all carry) and `bin/icons` renders the 192 and 512 PNGs from it — deliberately outside Rails, because ActiveStorage blocks libvips' SVG loader on boot and unblocking a real protection to render a file we ship ourselves is a bad trade. The dot's 52% diameter fits the maskable safe zone, so one image serves `any` and `maskable`. And **`viewport-fit=cover`** comes with it, because `env(safe-area-inset-*)` reports zero without it and the nav's new bottom toggle offsets by it; the cost is a landscape notch cutting into the rail, paid back by `.nav-rail`'s `padding-left: env(safe-area-inset-left)`. Verified by asking Chrome itself what it parsed (`Page.getAppManifest` over CDP): zero parse errors, both icons fetched, the Today/Calendar/Tasks shortcuts present. `test/integration/pwa_install_test.rb` pins reachability without a session, the fields an install prompt needs, icons that are the size they claim with no alpha channel (a transparent ground renders black on an iOS home screen), and the absence of scaffold placeholders — the first of those caught the format bug above. Offline caching is deliberately *not* part of this: a service worker that serves stale pages is a bug factory, and `public/service_worker.js` stays what it is, web push and nothing else. Installing also hands the left screen edge back from the browser's back gesture, which is the one context where the nav's edge swipe works in full — and changes nothing about the button, which stays the affordance because a browser tab is the common case. See D-installable.
