**Two leftovers from the chat wave's install pass (`docs/CHAT_PLAN.md` W5)**: this branch built W5's manifest half — a static `public/manifest.json`, a `theme-color`, a service-worker registration — and then `origin/main`'s own PWA wave landed the same ground and did it properly: a Rails-served `manifest.webmanifest` with shortcuts, real icons rendered from an SVG source whose dot sits inside the maskable safe zone, and `pwa_install_test.rb` checking the served bytes rather than a file on disk. The static manifest and its test were **deleted in the merge** rather than reconciled: two manifests is a bug, and main's is better on every axis. Two things survived because main has neither. **`apple-mobile-web-app-status-bar-style: default`** keeps iOS's status bar *outside* the web view once installed, which is what makes `100dvh` still mean the area the app actually has — the chat screen (D-chat-shell) sizes itself against exactly that, so `black-translucent` (prettier, and needing a top safe-area inset on every page) would have quietly broken it. And **the service worker now registers on page load** rather than only when somebody clicks "Enable browser push" in Settings (D22), so almost nobody had one; registering is idempotent, and it is scoped for free because `layouts/public.html.erb` ships no JavaScript at all, so a share-link visitor registers nothing. Still open and still a decision rather than plumbing: **a `fetch` handler in the worker**. Chrome will not raise its install prompt without one, so today the manifest improves iOS Add-to-Home-Screen and does *not* make Android installable — and adding one routes every request in the app through the worker, which is a call about offline behaviour for an app holding one household member's private data. **Noted, not fixed (pre-existing, from the vault commit):** the CSP nonce is `request.session.id`, which is empty before a session exists, so on signed-out pages (`/session/new`, password reset, invitation accept, first-run setup) the importmap and module shim are refused and no JavaScript runs. Nothing on those pages uses Stimulus today, so it is latent rather than live — but the day one does, it will silently not work.
