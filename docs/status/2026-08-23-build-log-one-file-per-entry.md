- **The build log stopped conflicting, for real this time (`docs/status/README.md`)**: `merge=union` on `docs/STATUS.md` made `git merge` keep both branches' appended lines, but GitHub computes PR mergeability without applying `.gitattributes`, so every parallel branch still *showed* a STATUS conflict that only a local `git merge origin/main` could clear — the workaround was documented in `CLAUDE.md`, which is a tell that the shape was wrong. Entries now live one per file under `docs/status/` (`YYYY-MM-DD-kebab-slug.md`), so two branches logging the same week share no line in any file and there is nothing for any tool to conflict over; adding to the log is an *add*, and adds don't collide. `docs/STATUS.md` keeps the log through August 2026 (closed to appends, union attribute retained so an old branch still appending merges rather than conflicts) and explains the split; `bin/status` prints both halves in order, which is now the way to read the log. The generalization is in the conflict-hygiene rules: **append-only logs append files, not lines** — reach for a directory whenever a list only ever grows and order is the only relationship between its items.
