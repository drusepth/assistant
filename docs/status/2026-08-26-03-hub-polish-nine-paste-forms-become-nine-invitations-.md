**Hub polish: nine paste forms become nine invitations, and the hub can mark things read**: a UI pass over the D-hobby-feeds hub, driven by seeding a realistic instance (eleven hobbies, feeds on three) and looking at it. Two of the findings were regressions the build itself introduced. **The empty-hobby card opened a paste form**, which is right for one hobby and wrong for nine: the screenshot was a wall of identical forms with the three cards that had something in them buried under it. The form now sits behind a `<details>` disclosure — the browser has had that element for a decade, and this needed no Stimulus — and `Panels::Hobbies#cards` orders live hobbies first with the catch-all always last, deliberately *not* by unread count, since a grid whose cards trade places every morning is one nobody learns the shape of. **Opening a story from a card left it unread**, breaking the rule `docs/READER.md` states outright: without mark-on-open, "unread" means "not explicitly dismissed". The card rows now ride the same `reader_controller.js` the river uses, and `FeedItemsController` takes a `surface` param so one code path re-renders the right shape into the right id — a river row streamed into a three-line card would have been a full-width list line inside a taste. **`/reader` had become hard to find** once its rail row was gone (a small text link on one section page was the entire way in), so the everything-view is a real button with its count. **Filing a stray feed took three screens**: the feed list now carries an inline "File under…" picker on catch-all rows only, `/feeds?unfiled=1` narrows to the strays, and the hub's Other Interests card links straight there. **`classified_at` was invisible** despite existing precisely to tell "the model looked and chose nothing" from "the model never looked" — the row says which, which is also what tells you whether Re-file will do anything, and Re-file now appears only on rows where it can change something. Plus **keyboard navigation** (`river_controller.js`: j/k/o/m/s, Google Reader's keys, with the selection living in a DOM attribute rather than an index because rows leave the list as they are read, and the selected row revealing its verbs since a keyboard reader can't hover), `title` attributes on truncated headlines, `mt-auto` so card footers line up, per-hobby Mark all read on the lens page, and the starter shelf flowing in CSS columns instead of a grid whose rows are as tall as their tallest cell. 1756 tests green; the hub, the card mark-read, and j/k/m were driven in a browser. One thing left alone deliberately: `diary_habit_test.rb:70` has been failing since before this branch, because today's rotating diary prompt happens to be the exact string the entry form uses as its fallback placeholder.
