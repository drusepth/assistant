**Pronouns generalize from pets to people, and the model surfaces are finally told (D-pronouns, renamed from D-pet-pronouns)**: The pets pass shipped a `Pet::Pronouns` value object, which was the right idea in the wrong namespace — `Person` had the same problem and no column to fix it with. Now: one top-level `Pronouns` (subject, object, possessive, reflexive, plus `verb` and `is` for the agreement "they" forces, and `slashed` for prompts) and a `Pronounced` concern over a `pronoun` column, included by both. **The interesting finding was where the bug actually lived.** A sweep of every people surface — views, controllers, flashes, `Watcher::StayInTouch`, `Watcher::BirthdayRadar`, `People::Circles`, the components — turned up essentially *nothing*: the app's own copy about a contact was already neutral or already used singular they. The bias was one level down, in what the app tells a model. `person_context` sent a name, a relationship and the user's notes and **no pronoun**, so reconnect, gift_ideas and what_do_i_say left the model to infer one from the name — a guess dressed as knowledge, landing in a draft the user is about to send *to that person*. `gift_ideas` was worse: its system prompt's worked example read "[ask her sister] which authors she's into lately", teaching the guess in a way that would have out-argued any pronoun the record later supplied. So `person_context` now carries `Refer to them as: she/her/her` on every call — sent even when nothing is recorded, because "they/them/their" is the answer then and an absent line is what invites the fallback — the three prompts gained the instruction sentence the pet tools already had, and `email_follow_up`, which had a `Person` in hand and was sending only the name, now sends the pronoun with it. A regression test asserts no people prompt contains a gendered word at all. On the pets side the generalization bought a normally-blank `pronoun` override that beats the sex, which closes the one honest complaint about deriving: the household who calls their male cat "they" is no longer argued with. **`User` deliberately gets nothing** — no copy anywhere writes a pronoun about a household member (the app says "you", or their name), there is no profile view to set one in, and a column no sentence reads goes stale unnoticed; the trigger to revisit is the first prompt or line of copy that writes about a member in the third person. Demo contacts got pronouns matching the prose the fiction already wrote about them, with the vet left blank on purpose so the demo shows "they" reading fine.
