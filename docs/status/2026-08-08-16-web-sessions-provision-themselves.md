**Web sessions provision themselves**: `.claude/hooks/session-start.sh` (registered as a `SessionStart` hook in `.claude/settings.json`, remote-only via `$CLAUDE_CODE_REMOTE`) installs `libvips42` and runs `bundle install` before a Claude Code on the web session starts, so `bin/rails test` and `bin/rubocop` work on a fresh container. Without libvips the Active Storage variant jobs error and the suite reports six phantom errors that have nothing to do with the branch under test — the Dockerfile and CI both install it, only the web container was missing it. The apt step is skipped when `ldconfig` already sees libvips, and tolerates the blocked third-party PPAs in the base image (`apt-get update` warns; the Ubuntu archives still refresh).
