**The vet is a name you type**: the pet form's Vet field was a dropdown of existing contacts, so a household without their vet in the Address Book had to leave the form, make a contact, and come back. It is now a text box that suggests your contacts as you type (a native `<datalist>`, no JavaScript), with a phone box beside it. `Pets::VetContact` links an exact, case-insensitive name match (your own contact ahead of one shared with you) or makes a new ordinary contact with relationship "Vet". That puts the new vet in the Address Book and not the circle, which only holds people flagged keep_in_touch. The contact is still a full `Person` on purpose: tap-to-call on the pet's page, attaching to the appointment, and intake's `Landing::PetFacts` vet ref all need one, and a lighter kind of contact would have taught each of them a second case. Changing the phone updates your own contact, never one someone shared. The contact is created in the same transaction as the pet, so a form that fails validation leaves no stray contact behind, and it is auto-sorted only after the save commits. A form that doesn't carry the vet box leaves the vet alone.
