**Allergies on the Health hub: a note kind, a severity field, and its own block on the prep sheet**: D36's medication shape, one rung further (D-allergy-notes, docs/HEALTH.md §8). An allergy is a `Note` with `kind: "allergy"` — allergen as title, reaction as body — filed under Health by an Allergies card that sits under Medications on the hub. The one thing it adds is `notes.severity` (severe / moderate / mild, nullable): a narrow primitive-level column in the `events.care_kind` mould, earned because severity is the only fact about an allergy that changes what anybody does about it. It stays optional — the select defaults to "Not sure", and the `by_severity` scope sorts unrated allergies *last* rather than as mild, because an unrated allergy is an unanswered question, not a small one. Severe ones carry a red chip; the card removes as well as adds, since allergies get outgrown and the list you're reading is where you notice. `Tool::DoctorVisitPrep` now lists them as their own worst-first block ahead of the notes dump, with the prompt told to repeat them verbatim near the top of the sheet — the "call the list out explicitly instead of diluting it in generic notes context" rung D36 named, taken where dilution costs the most. That block deliberately ignores section tags: an allergy is one whether or not the note ever got filed under Health. Two things stayed out on purpose — cross-reactivity and med-interaction warnings, which are diagnosis wearing a helpful hat. One trap worth remembering: excluding the allergies from the generic notes listing needs `where(kind: nil).or(where.not(kind: ALLERGY))`, because a plain note's `kind` is NULL and `kind != 'allergy'` is NULL — not true — for every one of them; it silently emptied the Health-notes block until a test caught it, and now lives in `Note.except_allergies` with the reason attached. New files only, apart from the note model, the Health panel and its partial, the routes list, and the prep tool — no shared section file touched (D37).
