**The chat shell and instant send are built (`docs/CHAT_PLAN.md` W1 + W2, D-chat-shell / D-chat-optimistic)** — the two that made the surface feel homemade on a phone. **The shell**: `_chat` takes a `layout:` local and splits into `_chat_shell` + `_screen_bar`; a live chat run is now a *screen* that owns the viewport (`.chat-page` sized to viewport − `--app-header-h` − `--keyboard-inset`, with `.chat-screen` as `flex-1 min-h-0` inside it) so the transcript is the only scroller and the composer is welded to the bottom, reachable without a gesture. Below `lg` the page header, its date subtitle, its buttons and the recap footer all fold into one compact bar (back · title · overflow menu), which is roughly 120px of a phone handed back to the conversation; the task page's embedded panel becomes a **door** below `sm` (`GET /tasks/:id/conversation`, rendering with a possibly-nil run exactly as the panel does), because a card that is itself a scroller inside a scrolling page is the bug the screen exists to fix. Four corrections to the plan as written, all found by driving a real browser: the height arithmetic belongs to the **page**, not the screen (the first attempt sized the screen and the laptop scrolled by the height of its own header); `min-h-screen` on the layout wrapper had to go for a bleed page, since it stacks a full viewport *under* the mobile header and the document then scrolled by exactly the header's height; the header height became a token (`--app-header-h`, read by the header that has it and the page that subtracts it) rather than a second magic number beside the `20rem` it replaces; and **the planned `chat-scroll` sentinel rewrite was dropped as wrong** — an IntersectionObserver cannot tell "the reader scrolled away" from "content grew below them", which is the only thing the `autoScrolling` flag is for, so the flag stays and only the cheap half (`overscroll-behavior: contain`, which stops a flick at the top of the history firing the browser's pull-to-refresh) shipped. The keyboard is handled on both platforms: `interactive-widget=resizes-content` for Chrome on Android, and `chat_viewport_controller` measuring `visualViewport` for iOS Safari, which ignores the hint — the same measurement is ~0 on Android because `innerHeight` shrank too, which is why one implementation is correct on both. **The iOS zoom bug is fixed app-wide, not just in chat**: Safari zooms in on any field under 16px and never zooms back, every field here was 14px, and the rule is scoped to `(pointer: coarse)` rather than a breakpoint because a phone in landscape is wider than `sm` and would have kept it — pinned in `mobile_layout_test.rb`, a regression invisible on a desktop and ruinous on an iPhone. Quick replies became one sideways-scrolling row that hides once you have a draft, and the composer asks the on-screen keyboard for the right shape (`enterkeyhint`, `autocapitalize`, `autocorrect`) plus the gesture-bar inset. **Instant send**: the bubble is drawn, the composer cleared and locked, and the reply's dots started, all before the fetch leaves — and half of D-chat-optimistic was deliberately *not* built, because a turn changes more than the transcript (the lock, the chips, the recap affordance, the retry button, the indicator) and replacing one morph with five targeted streams buys nothing a reader can see for a large regression surface. What makes it seamless instead is a `client_token` column: the drawn bubble carries the id, the form posts it, the server stores it, and `_message` renders the real turn under the same id, so the morph *matches* the two rather than swapping one for the other. One ordering fact is load-bearing and was a real bug first — Turbo captures the request body when it constructs the submission, so the token is stamped on `submit` and the composer cleared on `turbo:submit-start`; clearing it a moment earlier posted an *empty* message, which every test passed and the first browser run caught. Drafts now also survive a navigation (`localStorage`, beside the offline queue) rather than only a morph. Verified end to end at 375pt and 1280pt: one scroller, no document scroll, composer on screen, 16px input, bar on the phone and page header on the laptop, the door-vs-panel split both ways, and the sent turn painted at 120ms then reconciled to exactly one copy under the client's own id.
