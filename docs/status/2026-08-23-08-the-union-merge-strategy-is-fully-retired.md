**The union merge strategy is fully retired**: splitting the build log into per-entry files removed `docs/STATUS.md merge=union` from `.gitattributes`, and no file in the repo carries a custom merge strategy any more (`git check-attr merge` over every tracked file comes back empty) — hub files like `routes.rb`, fixtures and `Tool::SLUGS` stay on the default strategy on purpose, because their keep-both conflicts deserve eyes. The three surviving mentions of `merge=union` are deliberate history, explaining in `.gitattributes`, `CLAUDE.md` and `docs/STATUS.md` why the strategy is gone. Removing it turned out to have a trap of its own, which cost one silent bad merge on the first branch to merge past the split: **git resolves a merge using the merging branch's `.gitattributes`, not the incoming one**, so a branch cut before the attribute was dropped still unions — and union on a file whose entry list `main` had just *deleted* resurrects that list, quietly reverting the split with no conflict, no markers, and nothing in the merge output to notice. `CLAUDE.md`'s conflict-hygiene section now records the general form: whenever a merge strategy changes, read the affected file's diff before committing the merge that brings the change in.
