**The /about pages: the spine, and the first pages on it**: the app now explains itself, to the person deciding whether to run it and to the person already running it, from one set of pages under `/about` that ships with the code (D-about-pages, `docs/ABOUT_PLAN.md`). Waves 0 and 1 together: the registry (`About::Page`), the controllers, a bare documentation layout, the household switch, and enough real pages to prove the shape — the front door, `privacy`, the Money hub, the Budget feature page, the two cross-cutting hubs, and a page for every one of the 57 tools generated from what the tool classes already declare. Three things worth knowing next time. Every page is the same bytes on every install — no household name, no counts, no enabled-section list — which is what makes the tree safe to expose and what turns the switch from a leak patch into a preference; a test asserts it. The switch gates *anonymous* access only and answers with a 404 rather than a 403, and `robots.txt` had to become a route, because the static file would have gone on advertising `/about` to crawlers on the very installation that turned it off. And the prose is optional per page: a hub falls back on generated tool cards, so the remaining nine can land one at a time — except the two hubs that own no section, which generate nothing and so must ship prose, pinned by a test.
