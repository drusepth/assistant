**The diary is built: a second sealed container behind the keyring** (`docs/DIARY_PLAN.md` W0–W4, D-diary-vault, D-vault-sealed): a private journal at `/diary` in the Vault sidebar group. **W0** extracted the password vault's machinery into `VaultSealed` (the item-key envelope, parameterized by payload column, AAD and an `after_sealing` hook), a `VaultSession` cookie registry, a `Keyring#reset!` hook registry, and a `Vault::Share` that takes any sealed record — with the password suite passing **unmodified** as the acceptance test. Two bugs the new invariant tests caught, both silent in ordinary use: Rails' cookie jar is keyed by name alone (two `Set-Cookie`s under one name = one cookie, last write wins, one surface left locked), and `cookies.delete` returns early for a cookie the browser didn't send (so a lock posted from `/credentials` would have left the diary unlocked) — locking now writes an explicit past-dated cookie per path. **W1** built the container with *no metadata tier*: title, body and the writer's own mood word are all inside the payload, `entry_date` is the only plaintext, so a locked diary renders its calendar and streak and literally nothing else. Owner item keys ride a GCM wrap under a per-user diary key (`DiarySetting`) rather than RSA, which is what makes a whole journal readable in one request; writing works while locked via an RSA wrap to the owner's public key, and the first unlocked read moves it onto the cheap wrap. The recovery kit is a **gate** before the first entry, not the nag it is on the passwords page. Two design corrections during the build: the diary key became an argument with an `ensure`-bounded lifetime after a key parked on the model silently decrypted past a vault reset, and the dials moved behind the unlock because a settings row created while locked is indistinguishable from one a password reset broke. **W2** added on-this-day (an index scan on plaintext dates), first-party writing prompts (no model call by construction), and search over decrypted payloads — dropped entirely while locked rather than echoed back. **W3** imports Day One JSON and Markdown (front-matter or filename dates; an undated file is skipped rather than filed under today) and exports Markdown with front matter, both in-request, with the round trip back through import as a test; the household archive carries no diary at all, not even dates. **W4** added per-entry read-only sharing with rotate-on-revoke, a polymorphic `VaultEvent` subject with `for_container` scoping so diary events never surface in the passwords vault's history, and the emergency dial — off by default, with copy saying plainly that the exclusion is the app's rule and not the encryption's. 1514 tests green.
