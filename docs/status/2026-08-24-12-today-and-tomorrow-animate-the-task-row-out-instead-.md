**Today and Tomorrow animate the task row out instead of vanishing it**: the reschedule pair on the Today screen was a `button_to` → `redirect_back`, so the only feedback for the page's main move was the row being missing from the page that came back (D-row-send-off). New `row-dismiss` Stimulus controller plus `.row-leaving`/`.row-gone`/`.btn-chosen` atoms: the tapped side goes solid and holds its pressed state, the loser fades back, the row tints to the winning side, then fades, slides 12pt, and collapses its height, padding and the stack's gap so the list closes up behind it (~400ms). The controller pauses `turbo:before-render` and resumes it when the row is done, so the render waits for the animation while the PATCH is in flight the whole time — free on a real network. Guards, all verified in a browser: a safety timer resumes the render whatever happens, a failed write puts the row back, the inline height/padding are cleared in the same task as `resume()` (morph matches these rows by position, so a leftover `height: 0` would land on the row that moves up), the 12pt slide stays inside what a row has spare in its card so the page never goes sideways on a phone, and the reduced-motion floor flattens the whole thing back to the instant removal it always was. Both new atoms are compound selectors (`.item-row.row-leaving`) because `.item-stack .item-row` outranks a lone class and would otherwise keep its own `transition-colors` and `bg-canvas`. Wired from `tasks/_task` only where the row offers the pair.
