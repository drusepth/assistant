**The dashboard hub board is built (`Assistant Dashboard.dc.html` 2a)**: the dashboard now ends in a board where every enabled top-level section is a card that links to its hub page, so the front door is a map of where the pressure actually is this week rather than one undifferentiated task list. `Dashboard::Board` computes it in two batched queries (no per-section N+1): an area with work goes **wide** (`sm:col-span-2`, up to `ROWS` task rows, overdue leading, "3 open · 1 overdue" in the header and "N more open" under the fold), a quiet one stays **narrow** with a single honest line ("Nothing due" / "Nothing needs you here this week"), and cards sort busy-before-quiet by overdue count — with `auto-rows-fr` keeping a "Clear" card the same height as the wide card beside it so the board reads as a grid, not a collage. Because sections are lenses and not silos, an item tagged Health + People shows on both cards on purpose, a task tagged only to a *subsection* rolls up onto its parent's card (a "Money · Subscriptions" task is Money's business), and a task tagged to both a parent and its child counts exactly once; everything reads through `visible_to` (D9), so another member's private work never reaches the board. The attention strip above it was restyled to the design's badge row — the headline count, then "N overdue" / "N due today" as separate chips, then "Open Today →" — and `test/services/dashboard/board_test.rb` pins the wide/quiet split, the overdue-first ordering, the row cap, the rollup, the dedup, completion, and the visibility boundary.
