**The chat plan gained a polish pass (`docs/CHAT_PLAN.md` W6/W7 + folded items, D-chat-index)**: a second read of the code rather than the screenshot turned up a missing floor and three live bugs the first pass hadn't named. The floor is **D-chat-index**: `resources :tool_runs, only: %i[ show destroy ]` means there is no index anywhere, so the only route back into a past conversation is a hand-placed link (the Health panel's "pick it back up" is the app's entire recall surface) and every other conversation is write-once until the 90-day prune deletes it — while `ToolRun#previous_recap` already renders "Picking up from last time", so the app implements resuming and gives nobody a way to ask for it; `GET /conversations` plus a "continue where you left off" head on `tool_runs/new` is one route and one query, and it ships alongside W1 rather than after it. **W7** takes back the three places the surface holds the turn hostage — the composer is `disabled: thinking` for the whole reply (no messaging app has ever done that, and the thought that arrives *while* you read is exactly the case these tools are for, so a message typed during a reply queues instead), streaming needs a Stop or the user watches a wrong answer arrive with no brake, and an offline phone should hold the queue and send when signal returns. Folded into the earlier waves: **`prefers-reduced-motion` appears nowhere in `app/`** and chat is the app's most motion-heavy surface (indefinitely bouncing dots, a smooth scroll per turn, soon continuous text), which for a vestibular disorder is the difference between usable and not; `.bubble` has no `overflow-wrap`, so a long URL or code span from a model is an unbreakable token that pushes the page sideways — the Narrow-screens failure still live in chat because the offending string arrives at runtime instead of from a view; `chat_body` renders inline code but not fenced blocks, so a tutor asked anything technical prints backticks; transcripts render whole with no limit; consecutive same-role turns don't group, which is the most reliable visual tell of a homemade chat; and `chat_input_controller`'s `pointer: coarse` test makes Enter never send on a tablet with a keyboard. The plan also now says out loud that **none of the keyboard work is verifiable from CI** — headless Chromium has no on-screen keyboard, no `visualViewport` offset, no zoom-on-focus, no safe area — so that half needs real handsets rather than a green build. Two questions parked: `Q-chat-suggested-replies` (chips from the turn, whose sentinel-vs-second-call cost lands on streaming) and `Q-chat-attachments` (waits on Q9's vision capability, must degrade honestly).
