**The Hobbies hub eats the reader: a plan for one river per hobby (D-hobby-feeds)**: design only — `docs/HOBBIES_HUB_PLAN.md`, no code yet. The reader shipped as its own rail destination with a three-item courtesy card on the Hobbies page, which had it backwards: the river is not a place you go, it is what makes each hobby different every day. The plan turns the hub into hobby cards that each carry their own three newest unread under the engagement line they already show, gives each hobby lens page a full river, and demotes `/reader` to the everything-view reached from the hub rather than the sidebar (routes unchanged, one nav entry moves, the unread badge lands on Hobbies). The question it exists to answer is per-feed versus per-story filing, and the arithmetic decides it: a subscription is added a handful of times per household, a story a hundred times a day (228 unread across eight feeds in two days on the instance it was designed against), so `Feeds::Classify` spends one model call per *feed* and stories inherit their feed's lenses at ingest for free. Broad feeds — news, aggregators, the case per-feed filing genuinely cannot serve — route per story by keyword match against each hobby's own vocabulary, itself generated once per hobby and editable on the lens: a rule you can correct beats a per-item verdict you cannot, it costs nothing, and it keeps the reader's third promise (an instance with no API key still works, it just files by hand). `FeedItem` becomes `Sectionable`, reversing one line of D-feed-reader for exactly the case that decision didn't have: one feed whose stories belong to different hobbies. Unmatched stories stay unfiled in an "Everything else" lane, which is both the honest home for world news in a Hobbies section and the input to a D20 watcher that asks whether forty climbing stories mean there should be a Climbing hobby. Feed text is a stranger's XML reaching a model prompt for the first time, so the classifier picks from a closed set of existing lens slugs and can never create one. Five waves, only the second of which needs a model at all; `Sections::Panel.for` grows a one-line parent-lens fallback so hobby pages get a panel without touching any of the three files D37 protects.
