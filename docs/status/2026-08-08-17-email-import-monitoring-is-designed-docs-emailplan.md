**Email import & monitoring is designed (`docs/EMAIL_PLAN.md`, D-mirror-layer / D-email-monitoring / D-mirror-database, revised across two design-review passes)**: mailboxes (plural — `multi: true` linked accounts with labels, every surface merged) sync over IMAP into a per-user **mirror layer** (D-mirror-layer) living in its **own SQLite database** (D-mirror-database — the life file stays the small copy-me backup artifact; the mirror is derived, re-syncable, excluded from export, soft-referenced only); messages become primitives only by explicit promotion or accepted suggestions, but mirrors feed read-only signals outward (People matching at ingest, opt-in contact recency from sent mail — Q8 revisited, watcher fuel later); sync distinguishes **backfill from live** (history is never triaged and structurally cannot alert; triage runs on live arrivals under a daily budget), direction detection rides a per-link learned own-addresses list, and the user can pause a link or tombstone-delete any message from the mirror; on top sit context-aware LLM triage behind deterministic sender rules (vip/mute via one-click feedback — the loop that makes week-two better than week-one), a `/mail` unified inbox with FTS5 search + promote buttons, a per-user-scheduled silent-when-empty daily digest (on D-household-profile's `households.time_zone`) + double-confirmed capped urgent alerts through the D22 channels with dials on the source (D-email-monitoring), a **boomerang family** (user-armed remind-me / expects_reply-gated no-reply / inverse unanswered) + follow-up draft tool, ask-your-email with live `read_archive` fallback beyond the mirror window, an IMAP IDLE listener for real-time alerts, a labeled triage eval corpus doubling as the injection regression suite, and an explicit hostile-input threat model (validated labels only, header-built notification payloads, cite-or-abstain answers) — eight build passes (E0, E1a/E1b, E2–E6) split along merge seams, platform work (multi-link, credentials encryption, recurring sync, household clock) first, sending mail explicitly deferred (Q19).
