**The build log became one file per entry**: `docs/STATUS.md` was a single append-only document that nearly every branch added a line to, which made it the most reliable source of merge conflicts in the repo — `.gitattributes` gave it `merge=union` so those appends resolved silently in git, but GitHub computes a PR's mergeability without the repo's attributes file, so every branch that touched the log still showed a conflict on its PR page and had to merge main locally just to clear a banner. The log is now one file per entry under `docs/status/`, named `YYYY-MM-DD-NN-slug.md` and read in filename order, so two branches write two different filenames and there is nothing to merge in either git or GitHub. `bin/status` prints the whole log, `bin/status tail 10` the recent stretch, and `bin/status new "What landed"` starts today's entry; the 68 existing entries were split out by their `git blame` dates with a within-day ordinal preserving the reading order, byte-for-byte, which also lifted the Money B1–B5 entries back to their real place in the chronology after union merge had stranded them below the "Next up" section. `docs/STATUS.md` keeps that "Next up" list and explains the scheme. The general lesson, now in CLAUDE.md: for a file everyone appends to, a merge strategy only quiets your own git — separate files quiet everything.
