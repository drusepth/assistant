**The conversation index, the offline queue, and the chat bug fixes are built (`docs/CHAT_PLAN.md` W6 + W7's offline third + the folded items, D-chat-index)**: the first slice of the chat overhaul, taken out of order because the missing floor and the outright bugs beat the polish. **`/chats`** (D-chat-index) ends the write-once conversation: chat runs are listed newest-turn-first — ordered by a correlated `MAX(id)` subquery rather than `created_at`, so a session you came back to today sorts above one you started today and abandoned — with two queries for the whole page instead of two per row, a preview line that skips `notice` rows (the app's own "try again" is furniture, not the last thing anybody said), a filter row that only appears once there is more than one kind of conversation to tell apart, section-coloured dots (sectionless `task_chat` takes a neutral one), and a task-bound run linking to its **task**, not to a run page, because that is its home under D30; the tool's own start page now leads with "Pick up where you left off" for chat tools, and the rail gains a Conversations entry, which is what makes the talking tools findable at all rather than reachable only from whichever section panel happens to link them. The **offline queue** landed ahead of W2's optimistic send on purpose — losing what somebody wrote is a worse bug than watching it appear slowly: a send with no connection is intercepted before Turbo sees it (Turbo's submit handler runs on the document in the bubble phase, so a `preventDefault` on the form wins), kept in memory and mirrored to `localStorage`, and drawn into the transcript as a dimmed bubble with its own Retry and Discard; it flushes on `online` and on the next `connect()`, and the three outcomes are distinguished deliberately — a network failure keeps the message and waits, a 4xx is the server genuinely saying no (the run is gone, or isn't a live conversation) and marks that one bubble "Couldn't send" instead of spinning forever, and a success drops it, with a single `Turbo.visit` at the end of the flush rather than one per message. Four bugs closed: **`prefers-reduced-motion` now has an app-wide floor** — unlayered and last in the file, because the cascade reverses layer order for `!important`, so an unlayered important sits below every layered one, which is exactly the priority a floor wants, and `.celebrate-banner` (which landed on main mid-plan as the app's only reduced-motion handling) opts out with a layered `!important` so its fade isn't flattened to nothing and lost; **`.bubble` gained `overflow-wrap: anywhere`** — not `break-word`, because a bubble is a flex item whose automatic minimum size is its min-content width and only `anywhere` shrinks that, which is why one long URL from a model could push a 375pt page sideways past the Narrow-screens sweep that pinned every other page; **`chat_body` reads fenced code blocks**, escaped and unwrapped inside a `pre` that scrolls in its own box, so a tutor asked anything technical stops printing backticks; and **Enter now sends on a tablet with a keyboard**, by a signal that is *learned rather than guessed* — every media query is wrong for some real device (`any-pointer: fine` would break newlines on a phone with a stylus), so a coarse-pointer device starts with Enter as newline and the first press of a key no virtual keyboard produces (Tab, Escape, a modifier, Home/End, PageUp/Down — arrows excluded, some Android IMEs send them) flips it for good. Driven in a real 375pt Chromium end to end: four pages with zero horizontal overflow, the absurd-token bubble at 263px inside a 375px viewport, the fenced block a scrolling `pre`, and the full offline round trip — queue, persist, survive a reload, reconnect, deliver, clear.
