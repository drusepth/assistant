**Reschedule says where the task went and offers an undo; rows get ids so morph and the keyboard keep their place**: two follow-ups to the send-off. **(D-undo-flash)** Rescheduling now sets a notice naming the task and the day it landed on, with an Undo button rendered inside the banner from a new `flash[:undo]` data key (`{"label" =>, "url" =>}`, silent like `celebrate`). The undo is just a reschedule back, so `to` grew to accept an ISO date and `"none"` alongside "today"/"tomorrow" — `"none"` is what makes an undated task undoable at all; anything unparseable still means today, as before. The banner is a `role="status"` live region, which on a morphing page is the only account of the move a screen reader gets. **(D-row-identity)** Rows and their buttons now carry ids: `dom_id(record, dom_prefix)` in `tasks/_task` and `events/_event`, bare `dom_id` in `tasks/_card`. Per-list prefixes on Today because `Event.overlapping` is inclusive at both ends and a meeting running today→tomorrow really is on two lists (a bare id would appear twice on one page — the new Today test proves it by failing the moment a prefix is dropped); deliberately no prefix on the board, where the columns are disjoint and a card moving column should stay the same node. Ids alone fixed nothing for focus: Turbo disables a submitter mid-flight and a disabled element can't hold focus, so it is gone by `turbo:submit-start`, before any morph. `focus_keeper_controller` on `<body>` (the one element a morph keeps) remembers the submitter's id and restores it after morph renders only. Measured before/after in a browser: completing a task on the board by keyboard went from focus on `BODY` — the top of the document — to focus still on that card's own button. Where the row was what the button removed, focus stays on body, which is correct.
