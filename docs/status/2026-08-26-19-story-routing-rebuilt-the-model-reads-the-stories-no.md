**Story routing, rebuilt: the model reads the stories, no words are matched (D-story-matching, D-no-keyword-logic)**: the version of D-story-matching that landed earlier today routed a broad feed's stories with per-hobby *term lists* — words the model wrote once, the user could edit, and `Feeds::Match` compared offline against every headline. It worked and it was the wrong mechanism, so it was replaced whole: **when the question is "what is this about", the model classifies.** A word list is a rule about an open subject; it fails silently on everything nobody enumerated, and every guard it needed (negatives, the 20%-of-your-river corpus test, the flood suspension, the per-term rejection tally) existed to patch the fact that it could not read. `Feeds::RouteStories` now asks the model, twenty stories a call, which of the user's hobbies each one is about — `Email::Triage`'s shape, validated into the closed set of lenses that already exist. The arithmetic D-hobby-feeds §2 used to refuse this was right about *every* story and wrong about the conclusion: `Feeds::Classify` now answers a second question in the call that already files a feed — is it about one subject or many — so a focused feed's stories inherit its hobbies forever for free, and only broad feeds' stories are read, once each (`feed_items.routed_at`), capped per run. A household with no broad feeds spends nothing. What the user owns became a **sentence instead of a rule**: a `HobbyBrief` saying what the hobby means, riding in the prompt beside its name, with a switch that turns routing off for that hobby; the model drafts one from the hobby's feeds and what was actually read there, and a sentence the user wrote is never overwritten. Corrections became **examples instead of adjustments** — "Not this" tombstones the routing and the title comes back in the next batch as something the user says is not this hobby, which is what a correction to a classifier actually is. Everything that was about the user rather than the mechanism survived unchanged: exceptions in their own table (now `story_routings`, with a `source` so a re-read never overwrites a human), D-feed-reader's invariant amended in one direction only, the river's single OR *inside* the authorization scope, counts on every surface that agree with what clicking them shows, and a hobby with no feeds of its own still getting a row, a card and a river. The honest cost: with no model configured nothing routes, where the keyword version gave a model-less box the feature via hand-typed words — the right trade, since a plausible wrong answer is worse for a self-hosted assistant than an honest absence, and a local model does this for free. The general rule is now written down once (D-no-keyword-logic, plus a standing rule in CLAUDE.md) with the one known exception named: `Spending::Categorize::KEYWORDS` still files transactions by merchant substring before its model pass.
