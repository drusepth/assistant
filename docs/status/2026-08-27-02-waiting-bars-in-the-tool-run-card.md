**Waiting bars in the tool-run card**: a queued or running tool run showed one grey sentence and nothing else, which on a phone reads the same as a page that has quietly given up. It now leads with `.working-bars` — seven rounded columns riding one wave, added as an atom in `app/assets/tailwind/application.css` beside the chat and celebration motion. The loop is one 1.4s `scaleY` keyframe shared by every bar, each offset by a seventh of the period, so the crest walks across the row and wraps into itself: nothing restarts, so there's no seam for the eye to catch on the fifth minute of watching it. Only `transform` animates — this can sit on screen for as long as a model takes, and a keyframe that touched height would relayout the card on every frame. Two details that aren't obvious from the rule: the bars carry a **resting** `scaleY` per `nth-child` rather than defaulting to full height, because the app-wide reduced-motion floor at the foot of the file collapses the animation to a single 0.01ms pass and what it falls back to should still be a shaped skyline rather than seven identical sticks (this atom *wants* that floor — a decoration saying "still working" adds nothing the sentence beside it doesn't, so unlike `.celebrate-banner` it doesn't opt out); and the whole group is `aria-hidden`, leaving the sentence as the only thing a screen reader meets. Below `sm` the bars stack above the text, since a phone-width card can't hold both on one line without squeezing the sentence into four words a row.
