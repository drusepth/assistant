**E1a (the email mirror + IMAP sync engine) is built** (`docs/EMAIL_PLAN.md` §4–5, D-mirror-layer/D-mirror-database): a fourth SQLite database (`mirror` in every environment, `db/mirror_migrate`, `MirrorRecord` base) holds `email_folders` / `email_messages` / `email_tombstones` / `email_message_items` — owner-private, no `Visible`/`Sectionable`, soft cross-DB ids only; `Email::ImapClient` (net-imap, read-only, friendly errors) + `Email::ImapSync` sync Inbox + Sent per link with two phases (bounded-batch backfill flagged `backfilled` and chained across job runs vs. live sync reporting `new_live_ids` for the E2 triage seam), UID cursors with UIDVALIDITY reset handling, message_id dedupe, tombstone respect, sent-folder-learned own-addresses driving direction, People matching at ingest, References-first threading with a strictly-gated subject fallback, bulk-mail heuristics, HTML→text bodies, attachment metadata only, and a recent-mail flag refresh; FTS5 rides model callbacks via `Email::Search` (lazy idempotent index, LIKE fallback, kept out of schema dumps); unlink purges the mirror through `Email::Mirror.purge` (promoted primitives survive), and `purge_orphans` sweeps mail whose link vanished without a destroy callback — the household reset (D-household-reset) calls it, since no foreign key crosses the two databases; `Email::PruneMirrorJob` (nightly recurring) enforces the per-link window with keep-exceptions (promoted / reply-armed / sender-ruled later); tests ride `FakeImapClient` + RFC822 fixtures per the plan's conventions.
