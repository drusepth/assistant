**The password vault is built (D-passwords-vault, D-vault-crypto, `docs/PASSWORDS_PLAN.md`)**: **Passwords** joins the sidebar's Vault group over `Credential` (Album precedent — `Visible`, never `Sectionable`, never in a prompt/log/job) with real envelope encryption: `Vault::Crypto` is the only file touching OpenSSL (PBKDF2-600k KEKs, AAD-bound AES-256-GCM, RSA-OAEP key wraps, RFC 6238 TOTP — no new gems), a per-user `Keyring` holds the vault key wrapped under the login password *and* a shown-once recovery code, and per-credential item keys are wrapped per reader in `credential_keys`, so sharing is one more row on the ordinary item-level `AccessGrant` and there's exactly one decrypt path. **Unlock rides sign-in** via an encrypted, HttpOnly, session-bound cookie path-scoped to `/credentials` (12h window, Lock button, re-unlock banner) — nothing at rest server-side opens a vault. Secrets leave only through `POST /credentials/:id/reveal` (no-store JSON, rate-limited, `visible_to` **and** a key row required); the index/show pages never render one, and copy/reveal/live-TOTP ride a `secret` Stimulus controller that overwrites the clipboard after 45s. Also: four kinds (login/wifi/card/note) from a registry with secrets as one versioned AAD-bound JSON payload; a client-side generator with random + diceware-passphrase modes; CSV import sniffing Bitwarden/LastPass/1Password/Chrome/Firefox; an in-request password-confirmed CSV export (the M4.2 archive carries credential **metadata only** — key material must never ride the job queue); a health panel (weak/common/reused/aging, computed in-request, never stored) over an offline common-passwords list on the D-public-datasets layer (`.txt` admin import, zero egress); revoke rotates the item key so a kept wrap opens nothing in future snapshots; and **emergency access** — the vault key escrowed to a chosen household member with an app-enforced waiting period, request/deny on the D22 channels, read-only release, honest copy that the wait is policy, not cryptography. Two pre-existing gaps closed on the way: the app had **no change-password form** (reset-only — and reset is exactly the flow that can't rewrap a password-derived key, so it gained a recovery-code step with an explicit-forfeit path), and it shipped with **no CSP at all** (the initializer was the commented-out scaffold; now nonce-based app-wide, because XSS is what turns a server-side vault into no vault). Deliberately unbuilt: browser autofill (Q-vault-autofill, the one still-open question) and the W6 agent dial (waits on actuators).
