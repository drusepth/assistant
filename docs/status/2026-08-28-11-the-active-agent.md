**The active agent lands, all five waves (`docs/AGENT_PLAN.md` A1–A5; D-suggestion-lifecycle, D-agent-prepared-work, D-decision-links, D-agent-earned-dials)**: "Active" used to buy cadence and volume only — a daily scan, the Today page, the notification channels — while the agent's *abilities* were identical at every dial. It now means the agent arrives with the work already done, and still lands none of it until the click. **A1** gave suggestions a lifecycle: a `resolved` status for what the world handled (distinct from `dismissed`, what the user waved away — opposite signals that the dial tuner later reads), an `expires_on` payload key checked without consulting any watcher, and `Watcher::Base#resolved?`, each watcher's own signal inverted in SQL, opted into by nine of them. The retire pass runs *before* the scan so a capped watcher spends its freed slots the same run, and `retires?` skips the query entirely for the twenty-three that don't answer. **A2** is the flagship and rides a seam that was always there: a watcher's `tool` action payload is a tool invocation nobody clicked yet, so the scan runs it and parks the draft on the suggestion — accept opens finished work, and Save on the review page *is* the D20 accept. The `Tool::Base` landing helpers gained a preparation mode that writes intents into `output["landings"]` and hands back unsaved records, so tool classes are untouched; but the guarantee that a speculative run leaves nothing behind is enforced by the **runner**, not by a rule tools follow — `Agent::Prepare` wraps the whole call in a transaction it always rolls back, which is what makes the four tools that create primitives outside those helpers safe without knowing preparation exists (their writes are undone and, having staged no intents, they prepare nothing and degrade to the plain prefilled redirect). Four gates, because this is the first thing the agent spends tokens on unbidden: Active sections only, a `prepare_work` switch, a configured model, and three attempts per scan — with Settings showing what was spent beside the switch that stops it. **A3** answers Q-sms-replies with the signed link, simplified twice by contact with reality: expiring rather than single-use (the session authorizes and decisions are idempotent, so replay is harmless), and packed by hand rather than through Rails' `expires_in:`/`purpose:` metadata, whose JSON wrapper measured a 212-character URL against a 300-character SMS bound — at 124 the link spends from the D-sms-channels budget rather than extending it, and the summary yields rather than the URL breaking. **A4** makes the dial earned: one sectionless model-free `dial_tuner` offers Active to a section whose suggestions get used (once ever — a dismissal is a permanent answer, which is what makes it polite) and offers to pipe down where they're dismissed on sight (once a year — going quieter must stay reachable), with two refinements that fell out of writing the counts: retired suggestions aren't ignored ones, and the tuner's own offers never feed its counts. **A5** regenerates the digest daily for anyone with an Active section. No new tables across any of it. The one thing worth remembering from A1: a fingerprint naming no subject we recognize now reads as "can't say", never as "handled" — the first draft treated an unparseable subject as resolved, which is right for a deleted row and catastrophic for a fingerprint format that changes, since it would silently retire every live nudge of that watcher on the next scan.
