**Household photos are built (`docs/PHOTOS_PLAN.md`, D-photos-primitive, D-storage-seam, all five waves)**: storage became a config seam first — `storage.yml` gained an ENV-driven S3-compatible service (AWS/R2/B2/MinIO, one shape) selected by `ACTIVE_STORAGE_SERVICE` with local disk the zero-config default, direct-upload JS wired, and `docs/STORAGE.md` covering vendor setup, the CORS policy, the mirror-then-flip migration, and backup posture. **Photo is the seventh primitive** (Visible + Sectionable): batch capture (drag-drop anywhere, per-file progress, multipart fallback; checksum dedupe skips copies), LLM-free `IngestPhotoJob` (EXIF capture time + GPS via libvips, pre-rendered stripped WEBP thumb/large variants — shared viewers never receive EXIF, coordinates render owner-only per Q14), a month-grouped keyset-paginated timeline with section/year/person filters, a Stimulus lightbox, and photos in the per-user export. **Albums** are user-owned containers (`albums`/`album_photos`, covers, delete-keeps-photos) shared through the existing grant machinery — `Visible` grew an `extra_visibility_clauses` hook and Photo's album clause is guarded by grantor-owns-photo so collaborative albums (Q15) can't leak; grid multi-select adds/removes in bulk, and the sharing card gained "share with everyone in the household" (bulk per-member grants, D9 intact). **People tagging** is manual (`photo_people`, the Q8 lesson) and names-without-granting; person pages show a photo strip. `/admin` gained a Storage panel (`Admin::StorageStatus` — service + per-member counts/bytes, never contents). Optional garnish: `ModelProfile.vision` (admin-declared "accepts images") unlocks Describe → `CaptionPhotoJob` (stripped variant as data URL through the one adapter; caption + suggest-and-click sections, auto-file only when untagged) and the **on-this-day** watcher (deterministic anniversaries ±3 days, one nudge per past year per year, new sanitized internal-`path` suggestion action whose accept opens the year-filtered timeline).
