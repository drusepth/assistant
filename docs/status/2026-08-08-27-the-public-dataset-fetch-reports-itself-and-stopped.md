**The public-dataset fetch reports itself, and stopped 403ing (D-public-datasets)**: the OES fetch failed on every vintage with `HTTP 403` — bls.gov's edge refuses a default `User-Agent: Ruby` before it ever looks for the file — so requests now identify the instance, try both spellings BLS has used for the directory (`special.requests` / `special-requests`), follow redirects, and start from *last* year's vintage (the May-YYYY file publishes the following spring, so the current year's never exists). A blanket 403 is now reported as what it is — a blocked instance, with the import path named as the way out — instead of a list of URLs. Reporting closed the two holes around it: the refresh job records the real exception (class and backtrace, not a re-wrapped `StandardError`), the **admin import path records at all** (any parser failure → `dataset_import:*` in the log plus a flash that says nothing was changed, where an unexpected error used to be a bare 500), and `Datasets::Status` puts each dataset's last failed fetch/import **on the /admin card itself** — dated, with the message, suppressed once newer data lands — so a failure nobody watched no longer reads as "not loaded" forever.
