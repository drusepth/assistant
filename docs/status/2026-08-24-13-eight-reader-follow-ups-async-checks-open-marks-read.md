**Eight reader follow-ups (docs/READER.md, D-feed-reader)**: the list of what I'd fix next, worked through. **"Check now" is a job, not a request** — `FeedsController#refresh`/`#refresh_all` enqueue `RefreshFeedJob` instead of fetching inline, because a stranger's server that hangs was holding a Puma thread for up to thirty seconds (10s open + 20s read); the row updates itself when the job lands, via a Turbo refresh broadcast to the user's `:reader` stream, and *only* when something actually changed — a page-refresh every fifteen minutes for a polite no-op check is worse than no refresh. Adding a feed still fetches in the request, on its own shorter timeouts (`Web::Fetch` takes them per call now): a subscription that silently fails to exist is worse than a slow form, and discovery has to answer "is this a feed?" before there is anything to save.

**Opening an article marks it read**, which is what every reader has done since Reader itself; without it "unread" meant "not explicitly dismissed" and clearing a screen took two clicks an item. The headline link still just opens the source — `reader_controller.js` rides alongside and asks for the same Turbo Stream the Read button would have produced, so there is one code path and no redirector endpoint pointing at arbitrary URLs. A modifier or middle click is exempt: that is somebody stashing tabs, not reading. **And a row read from the unread list now leaves it**, replaced by a line of its own height — "✓ Marked read — <title> · Undo" — so nothing vanishes without a way back and nothing below jumps. The row knows which list it is in because the partial takes a `filter` local and the read path carries `from=unread`; "Mark all read" gets no undo and asks first instead.

**OPML in and out.** The format every reader since 2000 agrees on, and the only reason a reading list can survive its reader — the export-archive argument (D14/M4.2) in a format the rest of the world reads. OPML's nested outlines are folders and this app already has folders, so a hobby lens becomes a folder on the way out and a folder matches a lens by name on the way in. Import creates a missing lens **only when the user ticks the box**: silently adding thirty sections to somebody's taxonomy because their old reader had thirty folders is not an import, it's a mess. Nothing is fetched while importing; each new feed gets a background check. Junk (a folder with no feeds, a `javascript:` xmlUrl, the same feed twice) is skipped rather than fatal, and the file is size-capped before it is parsed.

**Conditional GET** finishes the politeness the interval floor started: every refresh echoes back the publisher's own `ETag`/`Last-Modified`, so an unchanged feed costs them a header exchange and us no parse. Two things worth keeping. `Last-Modified` is stored and sent **raw** — reformatting a date is how a working cache becomes a broken one. And `Net::HTTPNotModified` must be matched **before** `Net::HTTPRedirection` in `Web::Fetch`: 304 is a 3xx and Ruby makes the former a subclass of the latter, so a redirect-first `case` reads every 304 as "a redirect with no destination" — which is exactly the bug the first version had, and exactly what the test caught. `Web::Fetch::Page` grew `headers` (the two validators only — handing back the whole response would hand back Set-Cookie) and `not_modified`.

**The dormancy N+1 is gone**: `Feed#dormant?` used to count items per feed inside the sweep, so `RefreshFeedsJob` asked the database once per candidate. Reading an item now stamps `feeds.last_read_at`, so dormancy is a column read — pinned by an `assert_no_queries` around `dormant?` and `due_for_refresh?`. `read_all` bypasses callbacks by design, so it stamps the affected feeds in one extra statement. **The rail carries the unread count** (`nav_link_to` takes a `badge:`, zero doesn't draw, and it rides `nav-label` so it disappears with the labels when the rail collapses) — one memoized count per render, and paused feeds don't count. **And `feed_items.image_url` is dropped**: the river is text, and a column nothing renders is a column that rots. The parser still reads an entry's image and still refuses anything that isn't http(s) — the guard moved *into* `Feeds::Parse`, so the day an expanded-item view lands, the data is safe by construction and comes back with the view that shows it.

Driven in a real Chromium end to end: the rail badge reading 7, opening an article leaving "✓ Marked read … Undo" in place at the same row height, Undo restoring the headline, "Check now" returning immediately with the row updating to the real result afterwards, and the OPML file downloading with its lens folders intact. Still named as not-done in the doc: `j`/`k` keyboard navigation, an expanded item, a hard ceiling on *unread* items (pruning only trims read ones), and folders for the feed filter, which is a sideways scroll at thirty feeds.
