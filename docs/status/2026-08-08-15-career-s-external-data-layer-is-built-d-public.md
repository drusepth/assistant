**Career's external-data layer is built (D-public-datasets, D-career-web)**: **datasets** — two-layer local store (`storage/datasets/` from `RefreshDatasetsJob`/admin import over `db/datasets/` seeds, vintage always displayed): CPI-U annual averages seeded, OES/OEWS national wage medians by fetch (BLS API + streamed zip/xlsx parse) or `/admin` air-gapped import; consumers degrade to absence, never guesses; **real-terms-drift watcher** (flat comp timeline × risen CPI ≥5% → yearly heads-up with the arithmetic shown) and raise_case now cites on-file CPI drift + closest OEWS medians (optional role input). **Web** — `Web::Fetch` app-side floor (deterministic, private-range-refusing, size/redirect-capped, Nokogiri text extraction; injectable resolver) behind new `listing_url` inputs on interview_prep/tailor_application; `model_profiles.web_capable` (Settings checkbox) relaxes never-assert-current-facts into look-it-up-and-cite via `Base#web_capability_note`. **Job scout** — per-user `job_feeds` (kind sniffed: RSS/Atom, Greenhouse/Lever boards normalized to their JSON APIs, USAJobs with key+email headers; Career-page card) scanned by `Watcher::JobScout`, the sanctioned non-SQL watcher: one ranking call over Career+Hobbies+Education context, suggestions only, one per posting ever, accept opens tailor_application prefilled with the listing link. **Ask-then-send email applications** — the email provider grows an optional SMTP field, `Career::EmailApply` sends through the user's own linked mailbox (fails closed on missing link/scope/recipient), and the tailor_application run page's compose panel is the review: prefilled from the cover-letter draft, resume attachment picker, one explicit click; a send lands an Applied Event + follow-up task on the run. Email-only by design — no ATS automation, nothing app-initiated ever sends.
