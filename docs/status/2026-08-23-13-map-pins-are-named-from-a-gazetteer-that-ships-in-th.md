**Map pins are named from a gazetteer that ships in the repo (D-travel-facet)**: a pin said "12 photos · Jun 2019" because the map refuses to geocode against a lookup service — a reverse-geocoder's request log pointed at a photo library is the owner's itinerary — so the fix is the one the basemap already took: ship the data. `db/datasets/places.csv` is ~7,300 public-domain settlements (Natural Earth 1:10m populated places, 284KB) on the existing D-public-datasets layer, so an admin can drop in a denser gazetteer without waiting for a release — the CSV import now picks its parser by headers, since CPI and places are both `.csv` and are not remotely confusable once you have read row one. `Datasets::Places` does nearest-match in memory over one-degree latitude bands with a longitude pre-filter that knows about the antimeridian. What it can honestly say is bounded by what it holds: within 20km it says "Lisbon", within 100km "Near Lisbon", and past that nothing at all, because a gazetteer of cities has never heard of the village you stayed in. Nearest wins over most-famous (Kyoto stays Kyoto next to Osaka), and a missing or malformed file is an unnamed map rather than an error. Pins, the Places list, the Travel tiles and the timeline's place chip lead with the name and keep coordinates as the fallback; pins also group by country, which is what the zoom navigates by.
