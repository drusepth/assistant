**The decision log became a folder too**: `docs/DECISIONS.md`'s 91 entries are now one file each under `docs/decisions/`, named by ID (`D10.md`, `D-photos-primitive.md`, `Q17.md`), read with `bin/decisions` (`show`, `open`, `show D10`, `new D-slug "…"`) — the `bin/status` treatment, applied to the file that had become the second-most conflict-prone thing in the repo. The premise checked out before the work started: a scratch three-way merge of two branches each appending an entry conflicts every time, because both insert at the same anchor (the end of `## Decided`), and ~84% of the file's churn was pure append. **The argument that had kept it one file has retired.** CLAUDE.md said the log "stays on the default strategy on purpose: its conflicts are what force the D-number re-check" — true when IDs were a shared counter, dead once they became slugs, and the folder actually *sharpens* it: a slug is now the filename, so two branches claiming the same ID collide as an `add/add` conflict on that path rather than as a text conflict someone could resolve keep-both without noticing the IDs matched. Both properties were verified in scratch repos: two branches adding different decisions merge clean; two branches claiming `D-clash` conflict loudly. **The group is a line, not a folder** — each entry opens with `<!-- decided -->`, `<!-- resolved -->` or `<!-- open -->` and `bin/decisions` groups on it, so an open question becoming a decision is a one-word edit instead of a delete from one section plus an insert into another, which was the *other* way this file conflicted. IDs never change and files never move, so the by-ID cross-references from `ROADMAP.md`, `MONEY.md`, `EMAIL_PLAN.md` and eight other plan docs still land, and `docs/DECISIONS.md` survives as the front door explaining the layout (the `docs/STATUS.md` pattern). The split was scripted and verified lossless: all 191 non-blank source lines accounted for, zero duplicated lines, `bin/decisions` output identical in content to the file it replaced. One entry — Career's external-data questions — had never had an ID at all and got `Q-career-external-data`. `docs/DESIGN.md` still deliberately stays a single conflict-prone file, and CLAUDE.md now says why in the place that used to say it about this one: unlike the two logs it is *edited* rather than appended to, so a conflict in a design rule is the kind that deserves eyes.
