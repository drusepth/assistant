**Hardening the diary: autosave that covers the first sitting, undo, and a recovery kit that is proven** (`docs/DIARY_PLAN.md` W6): a pass over the seven places the first build was thin. **Autosave** only attached to an existing entry, leaving the longest stretch anyone writes without saving — the first sitting — unprotected; it now creates on first pause and re-points itself, the form and the address bar at the entry it made. That makes two-tab collisions ordinary, so entries carry a `lock_version` and a stale tab gets a 409 instead of silently overwriting; a side effect worth knowing is that `update_column` becomes a silent no-op on a stale record once optimistic locking is on (right failure mode for the opportunistic re-wrap that uses it, wrong one anywhere else). **`diary_revisions`** keeps the payload an edit replaced, sealed under the entry's own item key — no new key management, dies with the entry — throttled to one snapshot per sitting so a burst of autosaves can't bury the version worth having, and a restore snapshots first so undo is itself undoable. **Pagination** replaced a hard 200-entry cap that made older entries unreachable; **search** stops decrypting at its cap and says "the first 100" rather than "100" (`find_each` was the obvious tool and the wrong one — it discards ordering, which would have filled the first page with the oldest matches). **Import** now survives a real journal: a background job is forbidden here and a plaintext tempfile would undo the feature, so the parse is staged *sealed* under the diary key in `diary_imports` and walked a batch per request with the cursor in the database — a closed tab pauses an import rather than losing one, and a staging row that won't open (a password reset mid-import) ends the run with a sentence instead of looping. **`Diary::Markdown`** renders bodies that were already stored, exported and imported as Markdown but displayed as preformatted text under a CSS class that never existed; it's first-party because a general engine's job includes passing raw HTML through, and its safety argument is one line long — everything is escaped before a single rule runs, so the only tags on the page are ones it writes itself. Writing that rule down found its own bug: `>` is already `&gt;` by then, so blockquotes never matched. **The recovery kit became a proof**: `recovery_confirmed_at` recorded a click, so the code can now be pasted back and checked, and the diary's gate moved onto `recovery_verified_at` while the passwords vault still accepts the click — a mistyped kit costs a round of password resets there and the whole journal here. Plus the calendar rebuilt as a real table with per-day labels, container-appropriate copy when a sealed record can't be shared, and "on this day" widened to a few days either side, which for anyone but a daily writer is the difference between the feature appearing and not. 1583 tests green.
