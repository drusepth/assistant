**Pets get pronouns: sex is a closed set, and the copy stops calling every animal her (D-pet-pronouns)**: The pets build shipped with `sex` as a free-text box and every sentence about a pet hardcoded to *her* — the flash after adding one, the Food card's "What she eats, and since when", the filing card, the gone banner, the delete hint, the reorder alert, the tool hints and prompts. Half the pets in the world are not a her, and a pet whose sex nobody recorded is not one either. Free text is the shape that can't be fixed: reading prose for a pronoun is keyword-matching, and D-no-keyword-logic says no. So `sex` becomes `female` / `male` / blank, `Pet#pronouns` returns a `Pet::Pronouns` value object (subject, object, possessive, reflexive, plus `verb("eats", "eat")` and `is` for the verb agreement "they" forces), and blank is a real answer that yields *they* rather than an unfinished form. One field, not two: a form that asks for a cat's sex and then for the cat's pronouns is written for a power user, and the target user is not one. What the old placeholder invited into the same box — "neutered male" — is a *status*, so it's now its own checkbox, prints as "Neutered male" in the details line, and does not touch the pronoun. Model surfaces get the fact instead of a default: `pet_context` and the lost-pet poster carry `Refer to this pet as: he/him/his`, and both prompts are told to use it. Copy written before a pet exists (the "Add a pet" header, the tool hints, `pet_care`'s example prompts) went neutral, because at that point the app genuinely doesn't know. The migration normalizes only the spellings the old placeholder itself suggested and clears the rest rather than guessing — a cleared optional box costs one re-pick, a wrong guess costs trust in the whole record. Code comments keep their illustrative "her"; this was about what the app says to the owner.
