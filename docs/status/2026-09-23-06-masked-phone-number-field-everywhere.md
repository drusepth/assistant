**Masked phone number field everywhere** (D-phone-numbers): every phone box (a contact's phone, the pet's vet, the household phone) now uses one masked input. The user types digits, and the `phone-input` Stimulus controller fills in "(503) 614-9061" as they type. It keeps the caret in place for edits mid-number, and a backspace over a ")" or "-" deletes the digit before it instead of doing nothing. A leading "1" is dropped as the country code. A leading "+" switches to an international number: "+1" gets the North American mask after it, and any other country code is left ungrouped. A `pattern` attribute stops a half-typed number at the browser. There is nothing to opt into: `ApplicationFormBuilder#telephone_field` (and its `phone_field` alias) adds the controller, `inputmode="tel"`, `autocomplete="tel"`, a placeholder, and the stored number formatted for display, so `f.field :x, as: :telephone_field` is the whole API for any new phone field. On the server, `PhoneNumber.normalize` (through `normalizes :phone` on Person and Household) stores E.164 ("+15036149061"). Imports, the contact picker, and forms submitted without JavaScript all end up in the same format. A value it can't read clearly ("555-1234", anything with an extension) is kept exactly as written, and its edit box drops the pattern so it never blocks saving another field. A data migration converts existing numbers the same way. Views print numbers through `phone_link` / `PhoneNumber.format`, and so do the letterhead block and the lost-pet poster. The Address Book search matches a phone query by its digits, so "503-614" finds the number however it was stored. Known gap: no way to type an extension yet.
