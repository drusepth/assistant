**Quick-add dropdowns on every page**: the + Task / + Note / + Event / + Goal buttons outside the dashboard used to be links to `/tasks/new` and friends. Each one cost a page load there and another back, for a form that is only a title. They now open the same inline dropdown the dashboard hero uses, through one helper: `quick_add :task, prefill: { due_on: Date.current }`. `QuickAddHelper` builds the blank record the way each controller's `new` does, so a prefill (`due_on`, `goal_id`, `section_ids`, an event's `date`) means the same thing inline as on the page. It renders the kind's `_quick_form`, lands you back where you were via `return_to`, and namespaces field ids whenever two forms of a kind share a page. `Ui::QuickAddComponent` now carries its own `quick-add` controller, so it needs no page wrapper; opening one closes the others through a window event. It also takes `align:` (`:start`, `:center`, `:end`) so a button that isn't at the right edge still gets a panel on screen. Every panel has a "Full form" link to the new-item page that takes the typed title (or a note's body) along, so switching pages loses nothing; `goals#new` and `notes#new` now read that prefill. Converted: the Tasks, Events, Calendar, Notes and Today headers (Today's "Task for today" / "Task for tomorrow" keep their due dates), a goal's "Add task", a pet's "Add an appointment", and the empty-state capture on Notes, Events and section pages. Links that prefill from a list row stay links: the reader's "Task" verbs, the care radar's appointment links, and the calendar's per-day numbers. The hero card itself also lost `overflow-hidden`, which had been clipping these panels to its height.
