**The Address Book becomes a directory**: the roster drew every contact as a card in a three-up grid carrying a name and a `People` chip — the same chip on every card, on a page called People — while email, phone, address, birthday and last-contact sat one click away on the show page, so eight contacts filled a desktop screen with air. And there was no search, on the one page in the app with an **Import** button aimed at a CardDAV export. The grid is now one `.item-stack` under `.stack-label` letter headings with a sticky A–Z jump rail past twelve people (no new atoms — these are the list shapes the system already had). The row is wide because it now carries the addresses: `mail_to`/`phone_to` in aligned columns (both slots render even when empty, so numbers line up under each other whether or not the person above has an email), group chips minus the `People` parent that distinguishes nobody here, a birthday inside 30 days or the recency phrase, and `Log contact` on hover — dropped entirely on a phone, where there's no hover to hide behind and it would cost every row a third line. Reaching someone is one click, so there's no row of verbs duplicating what the text already is. Search is both a real GET form (deep-linkable, reaches into notes) and a Stimulus filter over a per-row `data-directory-haystack`, with rows, headings and rail all narrowing on the keystroke; `/` focuses, Escape clears, and Enter on a single remaining match opens that person instead of round-tripping a search whose answer is on screen. A miss offers to add the name you typed, prefilled. New `People::Directory` owns the querying: `NOCASE` collation (binary would file every lowercase name after Zoe), one grouped query for all the filter-chip counts, empty groups omitted, an unknown group slug filtering nothing rather than 404ing a stale bookmark. Circle mode is alphabetical now too, `stalest_first` and all — a directory's order is the thing you know before it loads, and staleness keeps its own surface in the People page's Reach out rows. The page also takes the name the nav has always given it (the *other* page titled "People" is the section dashboard). `people/_person` is untouched: the section page renders it two-up in a narrow column, and a directory line is a second honest shape for the same primitive. Nine controller tests and nine service tests, including one asserting the chip counts stay at a flat three queries however many groups exist. (D-address-book-directory)
