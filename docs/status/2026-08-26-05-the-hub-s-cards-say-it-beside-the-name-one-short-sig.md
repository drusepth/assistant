**The hub's cards say it beside the name: one short signal, no filler line**: "Nothing planned yet — dive back in" and "1 open task" each cost a card a row of height to say almost nothing, and the first of them said nothing at all. The engagement block is now a single short string right-aligned on the hobby's own name row — so what you *do* keeps its place above what you read (HOBBIES.md's named trap) without spending any height on it. One thing, most actionable first: a date beats a count, because a date is a commitment and a count is a pile, so it renders the next event's date ("Sep 3", with the event's own title on hover so the short version says what it is short for), else "2 tasks", else "1 project", else nothing — a hobby with nothing on says nothing, which is shorter than saying so and means the same. The catch-all uses the same slot for "no hobby yet" and drops its explanatory sentence. The grid also stopped stretching its rows (`items-start`): with stretched rows the shortest card in a row wears the tallest card's whitespace, which is the same wasted space in a different place — Guitar's one-story card went from 165px to 139px. Cards are ~35px shorter across the board and the phone layout has no horizontal overflow. Two tests moved with the behaviour: the hobbies panel test now asserts the short signal and the hover title, and `sections_controller_test`'s hub assertion checks the date-plus-`title` pair rather than the old two-line block (its Money subsection-tile assertions on "1 open task" are a different partial and untouched).
