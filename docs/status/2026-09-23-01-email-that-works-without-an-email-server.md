**Email that works without an email server**: the app no longer assumes anyone configured SMTP (D-instance-mail). Before this, a password reset on a typical install enqueued a mail to localhost:25 and told the user it had been sent, and the production mailer still carried Rails' `from@example.com` and `example.com` placeholders. Now **password reset** has two hand-delivered paths that need no mail at all: a **Reset link** button beside each member on the Household page (admin-only, never for yourself, rendered straight from the POST so the token stays out of flash and history, logged), and `bin/rails password:reset_link EMAIL=…` for the operator. Both mint a new `handed_password_reset` token that lasts 24 hours and dies on use; the existing reset form accepts either kind, and the vault/diary recovery-code step is unchanged. The forgot-password page only shows its email form when instance mail and `APP_HOST` are both set, and otherwise says who can hand over a link. **Instance SMTP** is read from `SMTP_ADDRESS`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` (plus `SMTP_DOMAIN`, `SMTP_AUTHENTICATION`) by `InstanceMail`, applied at boot outside test; port 465 gets implicit TLS, everything else STARTTLS. Production mail links now follow `APP_HOST`, whose resolution moved out of `Notifications::DecisionLink` into `AppHost` so the reset task, the mailer, and decision links share it. **Email notifications** can now send through the user's own linked mailbox (the SMTP settings moved from `Career::EmailApply` onto `LinkedAccount#smtp_settings`, which both use), with every TLS key spelled out so an instance on 465 can't leak its flag onto a mailbox on 587. Settings offers only the senders that exist and explains itself when there are none; a channel made before the choice keeps meaning instance mail. Operator guide in `docs/MAIL.md`.
