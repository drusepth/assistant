**Groups and the circle as one card grid, and the membership verb**: the People page answered "who's in your life" three ways — group chips carrying no faces and printing "People · Church", a special-cased "Your circle" row list, and the Address Book link. Now it's one grid of one card (D-people-circles): an avatar stack of member faces with a `+N` bubble, the plain name, one line of signal (next group event → a birthday inside it → what's in flight → an honest invitation), and two actions that end in contact. The circle is simply the first card, wearing an *Only you* chip — it stays a per-user flag rather than becoming a shared `Section`, so the boxes match without the privacy quietly matching too. The rows it earned survive as **Reach out** (the stalest few, one tap to log contact); the full circle is an Address Book filter, not a fourth surface. Underneath the visual fix was a functional one: group membership is a section tagging whose only writer was the picker in the person form's Advanced drawer, so groups were born empty — `People::Membership` plus *Add someone* on every card, a member panel on the group page (claimed by parent slug, since a group's slug is whatever the user typed), and a Groups line on the person page. New `Ui::AvatarStackComponent` renders through the existing avatar; stone left the face-tint cycle so the `+N` bubble can't read as one more face. Members batch in two queries however many groups exist, with a test that says so. `docs/PEOPLE_CIRCLES.md`.
