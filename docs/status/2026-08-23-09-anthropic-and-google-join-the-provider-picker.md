**Anthropic and Google join the provider picker**: two more presets over the one adapter (D10) — `anthropic` at `https://api.anthropic.com/v1` and `google` at `https://generativelanguage.googleapis.com/v1beta/openai`, both of which publish OpenAI-compatible chat-completions endpoints that take a plain API key as a bearer token, so neither needed a gem, an SDK, or a second code path. A household pastes a key from console.anthropic.com or aistudio.google.com, types a model name, and every existing feature works. What the work actually cost was the discovery that a preset is more than a URL (D-provider-presets): Anthropic's compatibility layer documents `response_format` as **ignored**, and this app passes `json: true` on nearly every call — every categorizer, every tool, every analyzer — so a URL-only preset would have shipped a provider that silently answers prose where the code expects a Hash. So `Llm::Client` gained two optional preset-driven knobs: `json_mode: :prompt`, which appends the JSON instruction to the **last user turn** (not a system message — Anthropic hoists and concatenates every system message to the front of the conversation, the worst place for a formatting rule), handling the multi-part vision array as well as the string case; and `max_tokens:`, the output cap Anthropic's underlying Messages API wants on every request. The existing fence-and-prose salvage is the second net under it. The picker also learned per-provider hints and a suggested model name that follows the dropdown but never overwrites one the household typed themselves. The boundary this sets for the next provider: a preset may declare *how* to ask for something the adapter already does, and may not bring its own request shape, auth scheme, or response shape — anything that does is a custom endpoint behind a proxy, or it isn't OpenAI-compatible and doesn't belong in the list.
