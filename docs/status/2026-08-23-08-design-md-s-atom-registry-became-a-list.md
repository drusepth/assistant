**`docs/DESIGN.md`'s atom registry became a list**: the "Atoms" entry under The layers was one prose paragraph naming every atom, and every branch that adds an atom inserts a word into the middle of it — which made it the file's reliable conflict site (it conflicted merging the display-face work into the Today redesign, one branch adding `.display` while the other added five). It is now one role per line, so two branches adding an atom apiece merge keep-both: the same reasoning CLAUDE.md already applies to the code hub files (`routes.rb`, `Tool::SLUGS`, fixtures), applied to prose. `DESIGN.md` deliberately does *not* follow the build log into per-file entries or a `merge=union` strategy — unlike the log it is **edited**, not appended, so union would silently duplicate paragraphs, and a conflict in a design rule is exactly the kind that deserves eyes. Merging the log split into this branch showed what that failure mode costs: `merge=union` on a `STATUS.md` that main had emptied into `docs/status/` kept both sides, resurrecting all 15 already-split entries into the file with no conflict marker to notice — the fix being to take main's copy verbatim and re-file this branch's own entries as new ones.
