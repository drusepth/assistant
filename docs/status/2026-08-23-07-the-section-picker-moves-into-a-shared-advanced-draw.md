**The section picker moves into a shared "Advanced" drawer (`shared/_advanced`)**: hiding the picker behind one collapsed line was the right shape but the wrong name — "Sections" is a specific thing, and every form has *some* control that shouldn't be the first thing you see. The disclosure is now a generic **Advanced** drawer, closed by default, that every form rendering the picker wraps it in (recipes, notes, tasks, events, goals, documents, people, photos). It's a **layout partial** on purpose: it yields, so it never learns what's inside it, and adding a second advanced control later means adding it to the block at the call site instead of teaching one shared file about eight primitives. Two locals keep folding-away honest — `hint` puts the state of the contents on the closed line ("Advanced — filed under Health and People", or "your assistant files this one" when nothing is set yet, from `section_filing_hint`), and `open` exists for the case that would otherwise be invisible: a validation error on something inside the drawer. The picker itself goes back to a flat fieldset now that the collapsing lives one level up, keeping the enabled-sections filter and the always-include-what's-already-applied guard.
