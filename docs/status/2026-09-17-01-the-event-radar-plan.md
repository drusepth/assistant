**The event radar plan (`docs/EVENT_RADAR_PLAN.md`; D-place-subscriptions, D-listing-feeds, D-event-radar)**: the design conversation for the ask HOBBIES.md §3–§4 parked behind Q9 — be told, ahead of time, about events near the places you care about that you'd likely want to go to, judged by your hobbies and interests. The app had nothing for this beyond `Tool::FindYourPeople`, which is honest about not being able to name a real club. The plan refuses the obvious build (ask the model for events near the user: the local models this project argues for can't browse, a timed search naming the household's coordinates and interests is a leak, and prose has no dates the code can trust) and makes the reader's move instead: **places** are the unit of subscription — gazetteer-named, radius + lead time, per user, never geocoded, a trip's located stay counting as a dated place — and **listing sources** attached to a place are where events come from: iCalendar feeds through the existing `Events::Import::Ics` (extended additively with `uid`/`url`/`geo`), pages carrying schema.org `Event` JSON-LD read as structured data and never as prose, and later an opt-in keyed provider (Ticketmaster Discovery) whose switch says out loud that it sends a location. Polled on the reader's politeness rules with a 6-hour floor; what lands is a **happening**, a candidate in its own table that reaches the calendar only by a click. Then the model reads each new series once against the closed set of hobby lenses (with their briefs) plus one owned radar sentence, twenty a batch, capped — the `Feeds::RouteStories` shape — and `Watcher::EventRadar` turns matches inside a place's lead time into ordinary D20 suggestions, five per place per scan, retiring on the date, resolving when the user adds it themselves, notifying through D22 with nothing new. "Not this" and dismiss both tombstone the match and return as examples in the next prompt (a new default-no-op `Watcher::Base#dismissed` hook). With no model: the river still shows everything by date and says the matching is off. Five waves: W1 places + sources + `/happenings` (shippable alone, no AI), W2 the match, W3 the watcher, W4 trip windows and "While you're there", W5 providers, Education subjects as targets, the Find-your-people follow-up that ends in `/places`. Not started.
