**CI was red on main, for three unrelated reasons**: every PR had been failing `scan_ruby` since the recipe box landed, and none of it was any branch's diff. (1) Rails' generated `bin/brakeman` unshifts `--ensure-latest`, which exits 5 the moment a newer brakeman is *published* — 8.0.6 shipped, the lockfile said 8.0.5, and the build went red on someone else's release day with nothing here changed. The flag is gone: upgrades are Dependabot's job, and this scan's job is to fail on our code. (2) Underneath it, a real weak-confidence `LinkToHref` warning: `recipes.source_url` is typed into a form, permitted straight through `recipe_params`, and rendered as an `href` — including on the public share page, which a stranger outside the household opens. `Recipe` now validates the scheme (every import path already did; the model is where they meet), and both views render through `recipe_source_url`, which re-checks at the point of use, because the validation can't reach rows stored before it. Brakeman is at zero warnings, no ignore file — the finding was fixed, not silenced. (3) `bin/bundler-audit` was red on a genuine sqlite3 advisory (GHSA-mwm8-39rw-8826, use-after-free); bumped to 2.9.6. The general lesson is (1): a check that fails on an upstream release rather than on your code is a build that breaks while you sleep.
