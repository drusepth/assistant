**The conversation surface is polished into a standard chat UI (D29 surface, no schema change)**: assistant turns now render a deliberately tiny markdown subset (`ChatHelper#chat_body` — paragraphs, bullet/numbered lists, short headings, bold/italic, inline code, linked-out URLs) over HTML-escaped text, so nothing a model emits can become markup while `**bold**` stops leaking as asterisks; user turns stay verbatim. The transcript reverts to natural DOM order (screen readers, selection, and copy-paste were getting the conversation backwards from `flex-col-reverse`) with a `chat-scroll` Stimulus controller pinning to the newest turn, following new turns only while the user is at the bottom, and offering a jump-to-latest button once they scroll into history; it grows to the viewport, with a floor only when a live transcript exists so an embedded task conversation still sizes to its openers. The composer becomes one rounded field holding the growing textarea and an inline send button (`.composer`/`.bubble` atoms, so the chat surface rethemes from the token file): the button ships enabled and is dimmed by JS on an empty draft, but only ever on top of the server's `data-locked` in-flight state, so a composer with no JS still sends. Quick replies now hide the ones the user already sent; timestamps appear on hover; notices read as system lines; the transcript is a `role="log"` live region; touch keyboards no longer get an autofocus pop (and gain Cmd/Ctrl+Enter). Sending a message and receiving a reply are both Turbo *page refreshes* (both composers redirect back to the page they are on; every chat job calls `broadcast_refresh_to`), and with no refresh method declared each one re-rendered the page and threw the reader to the top — twice per turn, worst on a task page where the conversation sits far down. The layout now declares `turbo-refresh-method: morph` + `turbo-refresh-scroll: preserve`, so those refreshes morph in place and hold their scroll (every redirect-to-self in the app gets the same smoothness, and `broadcast_refresh_to` has assumed morphing since Turbo 8); the transcript carries an id so a morph matches it rather than swapping it out from under its observer, and the composer re-applies its empty-draft dimming on `turbo:morph` since `connect()` no longer re-runs. "Save a recap" had drifted into two homes under two different conditions — it now lives once, under the composer, behind a single `ToolRun#recappable?` the recap action shares.
