# STATUS.md

Where we left off — what is built, oldest first, then what's next.

**One entry per line.** This file is touched on nearly every branch, and git
merges line by line: entries on their own lines mean two branches that add
different milestones merge automatically, and a genuine collision shows up as a
readable one-line diff. Please don't rewrap these into paragraphs or join them
up — that is exactly what made this log the most conflict-prone thing in the
repo when it lived inside `CLAUDE.md`.

## Built

- **Milestone 1 (Organize core, AI-lite — D13) is complete** and under test: the database layer (households/users/sessions, seeded sections taxonomy, six primitives, tagging, access grants with `visible_to`), the design system, the full Organize UI — CRUD for all six primitives, Dashboard, Today, Calendar, Documents vault (section filters), Goals boards (kanban), section pages, Settings (section toggles + section-level sharing), item-level sharing on every show page — onboarding/member management (D15: first-run `/setup`, link-based invitations, admin roles), and the one AI feature: document understanding (household `ModelProfile` configured in Settings → `Llm::Client` OpenAI-compatible adapter → `AnalyzeDocumentJob` → summary + section tags, auto-applied to untagged documents, suggest-and-click otherwise).
- **Capture is now zero-friction (D16)**: every primitive's new form is minimal (task = title, event = title + day, note = body, goal = title, person = name, document = file) and a per-primitive `Categorize*Job` auto-files sections plus implied dates/times/titles/relationships; date fields everywhere use the native picker + shortcut chips, and event forms use date + time parts (blank start time = all-day) instead of raw datetimes.
- **Tasks and Goals are now one section (D17)**: the Tasks page leads with a goal-capture input ("What do you want to accomplish?") → `BreakDownGoalJob` (one LLM call replacing `CategorizeGoalJob`) auto-creates 3–10 scheduled, section-tagged day-sized tasks and files the goal; below it a goals progress strip, then the Later/Today/Done task kanban (Today = pulled-in ∪ due/overdue; Done derived from `completed_at`). Goals lost their board and `backlog` status (active/done, auto-finish when the last step completes); goal pages have "suggest more steps" (append-only); task cards/rows show their goal as a flag chip; dashboard header has +Task/+Event/+Goal.
- **People has modular address-book import**: `People::Import` (parser registry — vCard 2.1/3.0/4.0, Google CSV, Outlook CSV, generic CSV fallback) normalizes contacts (multi-valued phones/emails/addresses; overflow lands in notes so nothing is dropped), dedupes by name, tags imports with the People section directly (no per-contact LLM calls), and `Person` gained an `address` column; UI at /people/import/new, linked from the People index; on supported mobile browsers (Chrome/Edge/Samsung on Android) the same page also offers pick-straight-from-the-phone via the Contact Picker API (Stimulus `contact-picker` controller serializes picks to JSON → `DeviceJson` parser, same pipeline, hidden where unsupported). Adding a format = one parser class in `app/services/people/import/`.
- **Calendar has the same modular import**: `Events::Import` (parser registry — RFC 5545 iCalendar covering Google/Apple/Outlook/feeds with TZID/UTC/floating times, exclusive all-day DTENDs, DURATION, cancelled events, and recurrence expanded into concrete events within a 1-month-back/12-months-ahead window honoring EXDATE and RECURRENCE-ID overrides, exotic rules kept as first occurrence + "Repeats:" note; Outlook calendar CSV; generic CSV fallback) dedupes by title + start time, folds organizers/links/categories into descriptions so nothing is dropped, and deliberately leaves imports untagged with no per-event LLM calls (Calendar shows all events regardless of section); UI at /events/import/new, linked from the Calendar header. Adding a format = one parser class in `app/services/events/import/`.
- **Milestones 2 (Tools) and 3 (Agent) are designed** — see `docs/ROADMAP.md` (D18–D20): section pages become Act/Attend/Browse zones; a Tool is a first-party context→LLM→draft-primitives pipeline (plan tools ride D17 breakdown, and Situations are plan tools, so Q7's eviction test rides this infra); the agent writes only to a `suggestions` table fed by deterministic watchers, with Off/Quiet/Active per-section dials.
- **M2.1 (Tools foundation) is built**: section pages lead with an Act zone of tool cards (`Tool.for_section`, subsection tools surface on the parent too) and the empty state is now tool cards + quick capture pre-tagged with the section (hidden fields through the minimal forms; hand-tagging keeps auto-sort away per D16); tools are declarative classes (`app/tools/`, `Tool::Base` DSL: title/sections/kind/inputs/prompt, explicit `Tool::SLUGS` registry per D11); a run is a `ToolRun` row (inputs/status/error + `tool_run_items` join to created primitives) driven by `ToolRunJob` with a Turbo-refreshing show page that doubles as history; the first tool is **Draft a dispute letter** (Rights → Disputes: picks a vault document, drafts a formal letter as a filed Note + up to 3 follow-up Tasks, filed under the tool's sections ∪ the document's).
- **M2.2 (first plan tool) is built**: "Learn something" (Education) proves the plan half of D19 with zero new schema — a plan tool is goal capture with framing (creates a plain Goal, hands it to the shared `Goals::BreakDown` with an optional `brief` injected into the one prompt; `plan!` = call + apply, extracted from `BreakDownGoalJob` and shared by both); a failed run leaves an ordinary retryable goal. Eviction was deprioritized (low-frequency, narrow) — Situations are now M2.4, "moving" first (that's the Q7 cross-section test), eviction on demand.
- **M3.1 (suggestions core) is built**: the agent's only write surface is the `suggestions` table (D20 — Sectionable, fingerprint-deduped per user so dismissed nudges stay gone, statuses pending/accepted/dismissed/snoozed with 2-week snoozes, JSON action payloads: task/event → materialized on accept tagged with the suggestion's sections, tool → redirect to a prefilled run form); watchers are deterministic SQL-only classes (`app/watchers/`, `Watcher::SLUGS` registry mirroring tools) run by `AgentScanJob` (skips disabled sections; weekly `scan_all` fan-out via Solid Queue recurring — the hardwired Quiet cadence); the first watcher is **checkup cadence** (no own Health event in 12 months and none upcoming → "book a checkup" suggestion whose accept creates a Today task; half-year fingerprint buckets let a dismissed nudge fairly return next half); surfaces: Dashboard "From your assistant" card (push) + section-page Attend zone between Tools and the item lists (pull), accept/snooze/dismiss on every row.
- **M2.3/M2.4/M3.2 + the digest are built**: the tool slate is doctor-visit prep (own Health items only; prepares, never diagnoses), cancel-subscription, reconnect (new `person` input kind), and "Plan a move" — the first Situation, one plan-tool class with a rich cross-section brief (Q7 satisfied); draft tools share `Base::DRAFT_FORMAT`/`handle`/`filing`, plan tools share `Base#plan_goal!`. Agent dials live on `user_sections.agent_level` (Off/Quiet default/Active) as a per-section select in Settings, honored by weekly (quiet+active) and daily (active-only) `AgentScanJob` cadences — loudest dial among a watcher's sections wins, sectionless watchers run Quiet. Watchers: checkup cadence, **stay-in-touch** (Q8 resolved: manual `people.last_contacted_on` via "Log contact today" on the person page; no signal → no nudge; accept opens Reconnect prefilled), **renewal radar** (upcoming renew/expir/lease events → heads-up with a lead-time task), **goal stall** (sectionless; files under the goal's sections). The weekly scan also writes `users.digest` via `Users::WeeklyDigest` — the one LLM use in the agent, phrasing only (deterministic facts in, 2–3 sentences out, silent failure), shown in the Dashboard banner.
- **There is now an ops surface (D23)**: `/admin` (household admins only, `Admin::BaseController` + the D15 admin flag; sidebar link above Settings) shows model-profile status, job-backend status, and an error log at `/admin/errors`; the swallowed-failure problem is fixed at the source — every best-effort `rescue Llm::Error` in the `Categorize*`/`BreakDownGoal`/`AnalyzeDocument`/`ToolRun` jobs now calls `AppError.record` (a self-rescuing writer to a 500-row ring-buffer table), so quiet-for-the-user failures stop being invisible to the operator. The hub reports counts, not contents, for other members' failures (D9 privacy holds), and the Solid Queue panel degrades gracefully because Solid Queue is production-only here.
- **Model calls now retry (D24)**: `Llm::Client` splits failures into `Llm::TransientError` (408/409/425/429/5xx, transport, invalid JSON) and permanent plain `Llm::Error` (4xx config, non-OpenAI-compatible response shape, everything tools raise by hand); the `RetriesModelCalls` concern gives all seven model jobs `retry_on Llm::TransientError, attempts: 4, wait: :polynomially_longer`, and each job's rescue opens with `raise if will_retry?(e)` so the old give-up path runs only on the final attempt — a pending retry leaves the document "processing", the run "running", and the goal "breaking into steps…" instead of flashing a failure, and one `AppError` is recorded per run rather than per attempt.
- **Milestone 4 is built** — see `docs/ROADMAP.md` §5 (D21–D22): **FTUE** (four skippable steps at `/welcome` — sections, agent voice, model for admins via the shared `shared/_model_profile_form`, importer launchpad — gated by `users.onboarded_at`; existing users backfilled; pre-auth controllers skip the gate); **api_key encryption** (AR encryption, per-instance keys auto-generated into `storage/active_record_encryption.yml` on first boot, backfill migration, `support_unencrypted_data` for old rows); **export** (`Users::Export` → own-data-only JSON-lines per primitive + document files + manifest, `ExportJob` attaches to `users.export_archive`, Settings button); **notifications** (D22: `notification_channels` — webhook JSON w/ ntfy-friendly Title header, Web Push w/ per-instance VAPID in `storage/web_push_vapid.yml` + `public/service_worker.js` + Stimulus subscriber, email via `NotificationsMailer` if SMTP exists; `Watcher::Base#proposals` → `AgentScanJob` fans out fresh **Active-dial-only** suggestions via `NotifyJob`, batched, titles-never-bodies, channels fail independently, expired push self-disables); **cross-user coordination** (D21 proven: `Watcher::SameDaySync` is an ordinary watcher whose only difference is `visible_to` scopes — you + a member both have timed events the same day within 14 days → heads-up + coordinate task).

- **The Hobbies section is built out (D25, `docs/HOBBIES.md`)**: hobbies are user-created child sections of Hobbies — the first user-written taxonomy rows (`sections.custom`, the only removable sections; items survive removal minus the tag; slugs dedupe against the global namespace and feed the LLM listing) — created via `Hobbies::Lens` from the Hobbies page's "What do you do for fun?" capture card (suggestion chips + free text) or by the Start-a-hobby tool; `Tool.for_section` surfaces parent-registered tools on subsection pages (and vice versa) so Hobbies tools appear on every lens page, and a `:hobby` input kind renders a lens picker (free text before any lens exists). Three Hobbies tools: **Start a hobby** (plan; creates the lens + a cheapest-first-taste Goal via `plan_goal!`), **What should I make next?** (draft; idea-menu Note from lens-tagged goals/notes/documents — evergreen framing, never presented as news), **Find your people** (draft; Tier-A-honest where-to-look guide on the shared DRAFT_FORMAT contract, never invents local venues; upgrades in place when Q9 resolves). Plus a fifth watcher, **neglected hobby**: a lens quiet for 6 weeks with nothing upcoming → one nudge whose accept puts an all-day session on the first free day (monthly fingerprint buckets, the goal-stall convention).

- **Connected accounts are built (D26)**: `linked_accounts` (per-user, one row per provider) links outside services — email/IMAP, address book/CardDAV, calendar/CalDAV, Facebook, LinkedIn — from a Settings card; providers are registry entries in `LinkedAccount::PROVIDERS` (adding one = one entry: label, credential fields, scopes), access is scope-gated per link defaulting to full access (only switched-off scopes are stored, so new provider scopes default on like section toggles), and consumers must read through `allows?` (fails closed). Credentials plaintext for now — encrypting them via the M4 AR-encryption setup is a pending follow-up.
- **Contacts + calendar sync are live (D26's first consumers)**: a shared `Dav::Client` (plain Net::HTTP, RFC 6352/4791 discovery + well-known fallback; accepts a direct collection URL too) powers `People::CarddavSync` → `People::Import` and `Events::CaldavSync` → `Events::Import` (REPORT time-range matching the Ics import window) — same dedupe as file uploads, read-only, scope-gated inside the service; registry entries name their consumer (`sync_service:`) and one `SyncLinkedAccountJob` dispatches, firing on link + "Sync now" button, recording `synced_at`/`sync_error` shown on the Settings card. Email/Facebook/LinkedIn don't sync yet.
- **OAuth direction is locked (D27, not yet built)**: one-click "Sign in with Google" via a project-hosted **link relay** — tiny, open-source, stateless (owns the OAuth app + fixed redirect URI, bounces callbacks to the instance, exchanges code→token, stores nothing), relay URL a config value with BYO client_id/secret as the always-available escape hatch, so it can't become a landlord chokepoint; D26 scope keys map to real OAuth consent scopes; Google provider ships contacts+calendar first (free verification tier), Gmail later (restricted scopes need paid CASA review; app-password IMAP covers it meanwhile).
- **Job failures can't vanish and errors are copy-pasteable (extends D23)**: `ApplicationJob` discards `ActiveJob::DeserializationError` (a record deleted before its job ran is routine, not a failed job) and grows an `around_perform` safety net that records any unhandled `StandardError` to `AppError` — with backtrace and best-effort user attribution from the job's arguments — before re-raising to the backend (skipping errors a `RetriesModelCalls` retry will re-attempt and errors the job already recorded itself); `AgentScanJob` isolates each watcher so one broken watcher logs and moves on instead of killing the scan; `/admin` shows backtraces (collapsed) and every error — `AppError` rows and Solid Queue failed executions alike — gets a paste-ready plain-text report (`AppError#report`) behind per-error **Copy** and per-list **Copy all** buttons, built for dropping into a bug report or an AI chat. Failed executions also get **Retry** / **Discard** / **Discard all** buttons (`Admin::FailedJobsController` → `QueueStatus`, shrugging off the missing queue DB outside production), and a `CategorizeGoalJob = BreakDownGoalJob` alias shim lets jobs queued under the pre-D17 name deserialize instead of dying as `UnknownJobClassError` — deletable once no pre-D17 queue could still hold work.

- **The high-impact tool wave is built (`docs/TOOLS_PLAN.md`, D28–D29)** — nine tools in five waves on three infra seams, all Tier A, chosen by stakes × frequency × counterfactual × feasibility: `Tool::Base` grew shared draft plumbing (visibility-walled `chosen_document`, `filing_sources`, `create_note/task/event` — deadlines land as all-day calendar **Events** — shared follow-ups/deadlines parsers, `bulleted_block` for code-assembled checklists) and `Tool::LetterBase` makes a letter tool ≈ a prompt; the letter family is `insurance_appeal` (appeal window on the calendar), `debt_collector_response` (FDCPA validation posture; court-summons warning appended by code), `deposit_demand` (document optional — one line of facts + placeholders suffices), plus `results_explainer` (comprehension-not-diagnosis; disclaimer + doctor-questions checklist appended by code).
- **Section-reading tools ride `Tool::Context`** — a section's visible items (active goals with step progress, events, notes, documents, open tasks) rendered as a budgeted prompt block behind `Base#section_context`, whole lines only, `visible_to` the only read path: `negotiation_prep` (Career/Renting/Bills — prep sheet + separate send-ready counter-message; never invents market rates, un-supplied numbers become placeholders naming what to look up) and `benefits_screener` (Money → Benefits — `:select`/`:checkboxes` input kinds joined the DSL with array params permitted generically; report grouped Likely/Worth-checking with the verify-footer + screening date appended by code, one application Task per likely program).
- **Tools compose by routing (D28)**: sanitized `next_tools` prefills stored on `tool_runs.output` (`store_next_tools` — registry-validated slugs, target-declared inputs only, capped/deduped), rendered as next-step cards, `ToolRun#next_steps` re-resolving at read time; `decode_letter` is the universal front door — plain-language triage of any scary mail (what it is, what if you do nothing, the options), model-classified filing, stated deadlines to the calendar, and the specialist tool offered with the document attached by code; entry points on document pages and vault rows.
- **Undated tasks can no longer silently vanish**: the Dashboard and Today page only query tasks by `due_on`, so an undated task that slid down the board's Later column was invisible everywhere else — now the Today page's Unscheduled card lists oldest first (the newest undated task is the one you just wrote down; the oldest is the one about to be forgotten), and a seventh watcher, **stale task** (sectionless; suggestions file under the task's own sections; goal-linked tasks stay goal-stall's beat), nudges about open undated Later tasks parked for 3+ weeks — at most three live nudges at a time (resolving one frees the slot for the next oldest; monthly fingerprint buckets per the goal-stall convention), and its accept introduces the `schedule_task` action: pulling the *existing* task into Today due today (stamped at accept time), rather than creating anything.
- **Chat is a tool kind (D29)**: `tool_run_messages` (user/assistant/notice — notices render in the transcript, never reach the model), `Tool::ChatBase` (opening message from owned context via `ToolRunJob`; `done` = live; `ChatTurnJob` replies over a 30-turn window, deliberately un-retried — a visible notice the user retries by typing beats silent background retries; failures recorded to `AppError`), the run page doubling as the chat surface (composer, col-reverse transcript, derived thinking indicator), and "Save a recap" (`ChatRecapJob` → one filed Note on the run) as the only primitive a chat produces. The `tutor` (Education) proves it: Socratic, learner-adaptive, guided homework — its system prompt carries the Education lens (Learn-something plans with step progress, past recap Notes), so each session opens knowing where the last left off.

- **Email import & monitoring is designed (`docs/EMAIL_PLAN.md`, D30–D32, revised across two design-review passes)**: mailboxes (plural — `multi: true` linked accounts with labels, every surface merged) sync over IMAP into a per-user **mirror layer** (D30) living in its **own SQLite database** (D32 — the life file stays the small copy-me backup artifact; the mirror is derived, re-syncable, excluded from export, soft-referenced only); messages become primitives only by explicit promotion or accepted suggestions, but mirrors feed read-only signals outward (People matching at ingest, opt-in contact recency from sent mail — Q8 revisited, watcher fuel later); sync distinguishes **backfill from live** (history is never triaged and structurally cannot alert; triage runs on live arrivals under a daily budget), direction detection rides a per-link learned own-addresses list, and the user can pause a link or tombstone-delete any message from the mirror; on top sit context-aware LLM triage behind deterministic sender rules (vip/mute via one-click feedback — the loop that makes week-two better than week-one), a `/mail` unified inbox with FTS5 search + promote buttons, a per-user-scheduled silent-when-empty daily digest (needs the E0 `households.time_zone` — half of Q12) + double-confirmed capped urgent alerts through the D22 channels with dials on the source (D31), a **boomerang family** (user-armed remind-me / expects_reply-gated no-reply / inverse unanswered) + follow-up draft tool, ask-your-email with live `read_archive` fallback beyond the mirror window, an IMAP IDLE listener for real-time alerts, a labeled triage eval corpus doubling as the injection regression suite, and an explicit hostile-input threat model (validated labels only, header-built notification payloads, cite-or-abstain answers) — eight build passes (E0, E1a/E1b, E2–E6) split along merge seams, platform work (multi-link, credentials encryption, recurring sync, household clock) first, sending mail explicitly deferred (Q15).

- **E0 (linked-account platform pass) is built** (`docs/EMAIL_PLAN.md` §10): providers can be `multi: true` (email first — one link per mailbox with a required user-facing label, uniqueness enforced in the model per kind, `display_name` = "Email — Work"); `linked_accounts.credentials` is now serialized-JSON **encrypted at rest** (text column + `encrypts`, backfill re-save in the migration, fixtures store plaintext JSON readable via `support_unencrypted_data`); links carry a sparse `settings` JSON (first key: `paused`) read through `setting`/`paused?`; background sync is recurring (registry `sync_every:` — email 15m, DAV hourly; `SyncLinkedAccountJob.sync_stale` fan-out every 5 minutes in `config/recurring.yml`, per-link `sync_due?` deciding); and households gained the clock — `households.time_zone` (+ optional `region`, the Q12 hint) with a `tz` helper, editable by admins from a Household card form (`HouseholdsController#update`).

- **E1a (the email mirror + IMAP sync engine) is built** (`docs/EMAIL_PLAN.md` §4–5, D30/D32): a fourth SQLite database (`mirror` in every environment, `db/mirror_migrate`, `MirrorRecord` base) holds `email_folders` / `email_messages` / `email_tombstones` / `email_message_items` — owner-private, no `Visible`/`Sectionable`, soft cross-DB ids only; `Email::ImapClient` (net-imap, read-only, friendly errors) + `Email::ImapSync` sync Inbox + Sent per link with two phases (bounded-batch backfill flagged `backfilled` and chained across job runs vs. live sync reporting `new_live_ids` for the E2 triage seam), UID cursors with UIDVALIDITY reset handling, message_id dedupe, tombstone respect, sent-folder-learned own-addresses driving direction, People matching at ingest, References-first threading with a strictly-gated subject fallback, bulk-mail heuristics, HTML→text bodies, attachment metadata only, and a recent-mail flag refresh; FTS5 rides model callbacks via `Email::Search` (lazy idempotent index, LIKE fallback, kept out of schema dumps); unlink purges the mirror through `Email::Mirror.purge` (promoted primitives survive); `Email::PruneMirrorJob` (nightly recurring) enforces the per-link window with keep-exceptions (promoted / reply-armed / sender-ruled later); tests ride `FakeImapClient` + RFC822 fixtures per the plan's conventions.

- **E1b (`/mail`) is built** (`docs/EMAIL_PLAN.md` §7): an owner-only unified inbox across all email links (sidebar "Mail" under Vault, shown only when a mailbox is linked) — account filter chips, FTS-backed search with a LIKE fallback, thread-grouped list with seen/bulk/awaiting-reply chips, and a backfill-progress banner counting the mirror; the message page shows the whole thread and carries the **promotion row** (`Email::Promote`: → Task / → Event on a chosen day, all-day / → Note / attachment → Document with bytes fetched from the server only at that moment, then `AnalyzeDocumentJob` and the D28 decode door take over) with provenance chips ("Became: …"), the user-armed boomerang ("Remind me if no reply by ___" → `reply_wanted_by`, outbound only, zero AI), and tombstoned "Remove from mirror"; person pages gained the owner-only **Recent correspondence** card over the ingest-time People matching.

- **E2 (email triage + the eval harness) is built** (`docs/EMAIL_PLAN.md` §6): `Email::TriageJob` labels live-sync arrivals only (chained from `SyncLinkedAccountJob`; backfilled history is labeled solely via a "Label this thread" button) — code pre-emption first (bulk → noise, zero tokens), then `Email::Triage` batches ~20 messages per call with a code-built owned-data context block (People/calendar/goals under a hard budget) and a hostile-input prompt, returning **strictly validated** labels (enum categories, 0–3 importance, real ISO deadlines within a sane window, capped strings; malformed entries dropped, never stored) under a per-link daily model budget (over-budget shortfall recorded to `/admin`, D24 retries, final-attempt failures silent for the user but visible to the operator); labels denormalize to `importance`/`expects_reply`, power `/mail`'s Needs-action/Time-sensitive filter chips and per-message label rows, and feed the eighth watcher **email-deadline** (sectionless, run on scans *and* right after each triage batch): a stated deadline becomes a heads-up suggestion whose accept lands the all-day Event (D20 held — triage itself never writes primitives); the labeled **eval corpus** (`test/fixtures/files/email_triage_corpus.yml`, ERB-relative dates, injection-shaped fixtures included) scores any configured endpoint via `bin/rails email:triage_eval`.
