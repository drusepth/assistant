**D-goal-shape. The model classifies each goal finite or ongoing; finite goals show percent, ongoing goals show momentum.**
"Make new friends — 11%" is a category error: friendship is not one-ninth done because one of nine generated steps is checked, and the number jumps around every time the plan is re-planned. Percent is honest only for goals with a real finish line ("watch Gossip Girl", "renew the passport"). So the breakdown call (`Goals::BreakDown`) returns one more field, `shape` — `finite` or `ongoing` — stored on the goal and never overwritten once set (D16 discipline; a later "suggest more steps" run does not reclassify). **Finite goals keep the percent climb** — it is the satisfying part and it is true. **Ongoing goals show momentum instead**: steps completed this week, or when there are none, how long since the last one — a framing that is honest across re-plans and never reads as a verdict on an open-ended aspiration. An unclassified goal (`shape` nil — hand-created with no model, or pre-dating this) falls back to percent, the status quo. This is one field on an existing call: no new model spend, no new pipeline, and squarely inside D-no-keyword-logic — the model answers "what is this", validated into a closed set.
