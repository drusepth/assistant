**D-career-web. The web arrives on three leashes: app-side fetch, a declared model capability, and ask-then-send.**
(1) **App-side fetch is the floor**: `Web::Fetch` — deterministic code fetching one user-supplied URL (size- and redirect-capped, private-address ranges refused via resolver check, text-only extraction) — powers paste-a-listing-link inputs and the scout, and works identically on frontier APIs and local 7Bs. (2) **Model-side browsing is a declaration, not a discovery**: `model_profiles.web_capable`, an admin checkbox for providers with built-in search; prompts then relax never-assert-current-facts into look-it-up-and-cite. (3) **The job scout** is the first sanctioned exception to D20's SQL-only watchers: it fetches per-user `job_feeds` (RSS/Atom, Greenhouse/Lever public boards, USAJobs — feeds and open APIs only, nothing ToS-fraught) and makes one ranking call over the Career+Hobbies+Education context; the **write surface is untouched** — suggestions only, one per posting ever, accept opens Tailor-my-application prefilled. (4) **Auto-apply is ask-then-send, email only**: the compose panel on a Tailor-my-application run is the review — the user's own linked mailbox, their edits, one explicit click; a sent application lands as an Applied Event + follow-up task. No ATS form automation, and nothing the app initiates sends anything. — *Built.*
