**D-address-book-directory. The Address Book is a directory: search, A–Z, and the addresses on the row.**
The roster rendered every contact as a card in a three-up grid carrying exactly two things — a name and a `People` section chip. The chip was on *every* card, on a page called People, so the only mark that varied between two contacts was the one that never varies; everything an address book exists to hold (email, phone, address, birthday, recency — all real columns on `people`) was a click away on the show page, and eight contacts filled a desktop screen with air. There was also no search, on the one page in the app with an **Import** button pointed at a CardDAV export: at four hundred contacts the page had no working affordance at all. So the grid becomes a directory — one `.item-stack` of `.item-row`s under `.stack-label` letter headings, in the shapes the design system already had, plus a sticky A–Z jump rail once the list passes twelve. The row is wide because it now carries the addresses: `mail_to`/`phone_to` links in aligned columns (both slots render even when empty, so numbers line up under each other), the groups someone is in as chips — never the `People` parent, which distinguishes nobody here — a birthday inside 30 days or the last-contact recency, and `Log contact` revealed on hover. Reaching someone is one click, not a page and then a click, so there is no separate row of verbs duplicating what the text already is. Search is a real GET form (deep-linkable, and it reaches into notes) *and* a Stimulus filter over a `data-directory-haystack` on each row, so the list narrows on the keystroke with rows, letter headings, and rail all narrowing together; `/` focuses it, Escape clears it, and Enter on a single remaining match opens that person rather than round-tripping a search whose answer is already on screen. A search that misses offers to add the name you typed. `People::Directory` owns the querying — one collated `NOCASE` sort (SQLite's binary collation would file every lowercase name after Zoe), one grouped query for every filter chip's count, and empty groups omitted because a chip leading to an empty page is worse than no chip. The page is also renamed **Address Book** to match what the nav has always called it, since the *other* page titled "People" is the section dashboard. Ordering is alphabetical in every mode including the circle filter, `stalest_first` and all: a directory's order is the one thing the reader knows before it loads, and staleness keeps its own surface in the People page's Reach out rows (D-people-circles), where recency order is the point rather than a surprise. `people/_person` stays exactly as it was — the section page renders it two-up in a narrow column, and a directory line is a second honest shape for the same primitive, not a replacement. — *Built 2026-08.*
