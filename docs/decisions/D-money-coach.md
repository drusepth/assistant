**D-money-coach. Money coaching is support, not advice — and faithfulness nudges are pace facts, never commentary.**
The D32 boundary translated to money: `money_coach` is a D29 chat tool (mode presets: buy-decision · spend less · money stress · plan the month) whose context is the code-built budget snapshot, Money goals, prior recaps, and — only when the D-career-signal timeline has data — an hours-of-work wage line, source named. The one guardrail that must not depend on model behavior doesn't: a code-appended not-a-financial-advisor notice opens every session (never sent to the model), the prompt forbids specific investment/tax/credit-product recommendations, and debt distress steers warmly to nonprofit credit counseling plus the app's own Debt/Rights letter tools (the 988 pattern). Tone contract: the coach defends the user's *own stated plan* back to them, never shames, offers the 48-hour wait as a move not a rule, and when the user says "buying it anyway," helps fit it in gracefully — the user disposes. `spending_review` is the facts half: code aggregates in, narrated review + ≤5 traceable cut candidates out, D28-routed to `cancel_subscription`/`negotiation_prep` prefilled. Watchers (`budget_pace`, `new_recurring_charge`, `price_hike`, `month_close`) are deterministic SQL over the mirror, per-envelope-per-month fingerprints, no-signal-no-nudge — no LLM in any signal path, no judgment nudges ever (the D36 lesson: an assistant that nags gets turned off). Full design in `docs/MONEY.md` §4–5. — *Built (B4 then B3 — the coach first, so the watchers' accepts could route into real tools). `Spending::Recurring` turned out to be the load-bearing piece: one cadence-and-amount detector serves both the new-subscription and price-hike watchers, which is why a hiked charge can't also masquerade as a new subscription. `debt_payoff_plan` (B5) inherits the same boundary as a plan tool.*
