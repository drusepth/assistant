**D-note-quiz. Any note can be quizzed; a note a quiz filed is a report card that points past itself at what the quiz was about.**
Retrieval practice is the highest-leverage mechanism in the education plan (D-review-scheduler), and the Education hub's `quiz_me` proved it works — but the syllabus is not the only place the user keeps things worth knowing. Notes are the other one, and rereading a note is exactly the study habit retrieval beats. So `quiz_note`: a chat tool bound to its note through `tool_runs.subject` rather than a form input, the way a task's conversation is (D30), opened by one button on the note page. No picker, because the note *is* the input (D16); sectionless, because the entry point is the note, not an Act zone. Notes shared with you count — being quizzed on a study partner's note is the same act as reading it — while the transcript stays private to whoever took it, like every run. Where a task hosts its conversation as a panel on its own page, a note's quiz is a session of its own: the note page starts one and lists the past ones, the run page holds the transcript. That split is now a flag on the chat tool (`hosted_on_subject`) instead of an assumption baked into the chat index and the run page that every subject-bound chat is a task's. **The second flavor is the interesting one.** A quiz files a recap note, so "quiz me on this" on that recap would quiz its prose — asking "how did you do?" back at you. A recap is a report card, not material, so it points past itself: `Note#source_run` reads D19's paper trail backwards to the run that filed it, and the quiz runs on that run's *topic*, the review cards it minted from the misses, and — for a quiz on an ordinary note — the note the material actually lives in, walking back up a chain of recaps to a bounded depth. Finishing one that reaches the syllabus is evidence there like any other: forward-only mastery through `Topic#advance!` (D-mastery-evidence), fresh cards into the FSRS queue, a `study_log` line. Finishing one on an ordinary note just files a recap, filed where the note is. Nothing is written until the user clicks Finish (D20), and with no model configured the button is absent rather than guessing questions. — *Built: `Tool::QuizNote`, `Notes::QuizzesController`, the note page's button and past-quizzes list.*
