**D-pet-pronouns. A pet's sex is a closed set, and it is what the app's own copy reads to pick a pronoun.**
Every sentence the app writes about a pet needs a pronoun, and until this landed every one of them said *her* — the flash after adding a pet, the food card, the filing card, the gone banner, the delete hint, the reorder alert, the tool prompts. That is wrong about half the pets in the world and wrong about every pet whose sex nobody wrote down, and it is the kind of small daily inaccuracy that tells the owner the app isn't really about *their* animal. `sex` already existed as a free-text string (`"Female, male, neutered male…"`), which is exactly the shape that can't answer the question: prose can't be read for a pronoun without keyword-matching it, and D-no-keyword-logic is the standing rule against precisely that. So the column becomes a closed set — `female`, `male`, blank — and `Pet#pronouns` returns a `Pet::Pronouns` value object (subject, object, possessive, reflexive, plus `verb("eats", "eat")` and `is` for the agreement "they" forces on every sentence built from it). **Blank is a real answer, not an unfinished form**: a stray cat's sex is often nobody's to know, and it yields *they*, which is also what a household who'd rather not say gets by leaving the box alone. Derived from sex rather than asked for in a second box, because a form that asks for a cat's sex and then for the cat's pronouns is a form written for a power user and the target user is not one. What the old placeholder invited into the same box goes to its own flag: **spayed/neutered is a status, not a sex**, so `neutered` is a boolean, it prints as "Neutered male" in the one details line, and it does not touch the pronoun. The model surfaces get the same fact rather than a guess — `pet_context` and the lost-pet poster now carry `Refer to this pet as: he/him/his`, and copy the app writes before a pet is in hand (the "Add a pet" header, the tool hints and example prompts) is neutral because at that point the app genuinely doesn't know. — *Built 2026-09. The migration normalizes only the literal spellings the old placeholder itself suggested and clears anything else rather than guessing at it: the field is optional and "unknown" is a real answer, so a cleared box costs one re-pick and a wrong guess costs the owner's trust in the whole record.*
