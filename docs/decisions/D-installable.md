**D-installable. The app is installable to a home screen; the manifest is routed, complete, and tested, and installing changes what's possible but never what's required.**
Everything PWA-shaped in the repo was still Rails scaffold: `manifest.json.erb` with `"theme_color": "red"`, a red-circle placeholder icon, a commented-out service-worker stub, and — the part that made the rest moot — **no route pointing at any of it and no `<link rel="manifest">`**. Wiring it up is squarely on mission: a self-hosted assistant that lives on the home screen next to the apps it's meant to replace is a different proposition from a bookmark, and it costs nothing anyone has to rent. Three things had to be true. **The manifest needs a pinned format**: Rails' own `PwaController` renders `pwa/manifest` in whatever format the request negotiated, and a browser fetches a manifest with `Accept: */*`, which Rails resolves to `:html` — so the JSON template is never found and the scaffold route, uncommented as-is, 500s. `application/manifest+json` is registered as `:webmanifest` and the route pins `defaults: { format: :webmanifest }`, which fixes the lookup and gets the spec's media type for free (worth having for anyone behind a proxy that content-types by what it was told). **The icons are generated, not hand-drawn**: `public/icon.svg` is the source — the terracotta dot on canvas cream that the header, the rail, and the sign-in page all carry — and `bin/icons` renders the 192 and 512 PNGs from it. That script is deliberately *outside* Rails, because ActiveStorage blocks libvips' SVG loader on boot (SVG is a hostile format from a user) and unblocking a real protection inside the app to render a file we ship ourselves is a bad trade. The dot's 52% diameter fits the maskable safe zone, so one image serves `any` and `maskable`. **`viewport-fit=cover` comes with it**, because `env(safe-area-inset-*)` reports zero without it and D-mobile-nav-reach's bottom toggle offsets by it; the cost is a landscape notch cutting into the rail, paid back by `.nav-rail`'s `padding-left: env(safe-area-inset-left)`. Installing also hands back the left screen edge from the browser's back gesture, which is the one context where D-mobile-nav-reach's edge swipe works in full — **and that changes nothing about the button**, which stays the affordance because a tab in a browser is the common case and always will be. — *Built: the route, the mime type, the rewritten manifest (with Today/Calendar/Tasks shortcuts), `bin/icons`, and `test/integration/pwa_install_test.rb`, which pins reachability, the install fields, icons that are the size they claim with no alpha channel, and the absence of scaffold placeholders. Offline caching is **not** part of this — a service worker that serves stale pages is a bug factory, and the existing `public/service_worker.js` stays what it is: web push, nothing else.*
