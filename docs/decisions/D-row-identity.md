**D-row-identity. Rows and their buttons carry stable ids, so morph matches them by identity and a keyboard keeps its place**
Every list row in the app was anonymous, which left idiomorph nothing to match on but position. Two things followed. The smaller one is that a *rendered-twice* record collides invisibly: `Event.overlapping` is inclusive at both ends, so a meeting running from today into tomorrow is genuinely on two of Today's lists, and one bare `dom_id` would have put the same id on the page twice. The larger one is measurable and was costing real users: **complete a task with the keyboard and focus was thrown to `<body>`** — the top of the document, the whole page to tab through again before reaching the next task. Rows now carry `dom_id(record, dom_prefix)` and their action buttons carry ids derived from it. **The prefix is per *list*, not per page**, and the two rules differ on purpose: on Today, where the same record can sit in two cards, each list names its own slot (`overdue_task_5`, `due-today_task_5`) — a task that moves lists is a row leaving one card and another arriving, which is what it looks like. On the board, where the three columns are disjoint, the id is deliberately *bare* (`task_5`) so that moving a card between columns is the same node changing place. The focus half needed one more piece: ids alone fixed nothing, because Turbo disables a form's submitter while the request is in flight and a disabled element is not focusable — focus is already gone by `turbo:submit-start`, long before the morph runs and long before idiomorph's own focus restoration could act. So `focus_keeper_controller` (on `<body>`, the one element a morph keeps) remembers the submitter's id on the way out and puts focus back on the way in, for morph renders only: a real navigation is a new page and belongs at its top. When the element is gone — the row was what the button just removed — focus stays on body, which is the honest answer. Measured in a browser before and after: board, complete by keyboard, focus `BODY` → focus still on the same card's button, now reading "Reopen". — *Built: ids in `tasks/_task`, `events/_event` and `tasks/_card`, the `dom_prefix` local, `focus_keeper_controller`, and a Today test asserting every row is named and no id is used twice — which fails on the multi-day event the moment a prefix is dropped.*
