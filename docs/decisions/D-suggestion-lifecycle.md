**D-suggestion-lifecycle. Suggestions retire when the world resolves them; watchers own resolution the way they own proposal.**
Book the checkup yourself and the "you're due for a checkup" nudge sits in Attend until hand-dismissed — an assistant that keeps bringing up handled things reads as broken (the D-reminders rule, restated for suggestions). New status `resolved` (retired by the world, distinct from `dismissed`, retired by the user); `Watcher::Base` gains `resolved?(suggestion)` — default false, so every watcher keeps today's behavior until it opts in — and `AgentScanJob` runs a retire pass after `scan`, with the same per-watcher error isolation. The checks are each watcher's signal inverted, in SQL, model-free. One shared rule needs no per-watcher code: a suggestion whose subject moment has passed retires, via an `expires_on` key in the action payload set at propose time. Fingerprint semantics unchanged: `resolved` never re-proposes; recurrence is the watcher's own fingerprint bucketing, as it already was. First wave of the active-agent plan because it fixes a live trust papercut at every dial and preparation depends on it — a prepared draft about a resolved situation is strictly worse than a stale nudge. Design in `docs/AGENT_PLAN.md` §3. — *Planned (wave A1); not started.*
