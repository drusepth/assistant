**D-row-send-off. A row that a button removes from a list animates out, and Turbo's re-render waits for it**
Today and Tomorrow on a task row are the main move on the Today screen, and they were the least satisfying thing in the app: `button_to` → PATCH → `redirect_back`, and the row is simply *absent* from the page that comes back. Nothing acknowledges the press, and the row nearest your thumb blinks out with no sign of which button did it or where the task went — the same problem D-task-celebration solved for the checkbox, in the register of feedback rather than delight. Now the tapped side lights up and holds its pressed state (`.btn-chosen`), the row takes that side's tint, and the whole thing fades, slides, and collapses so the list closes the gap under it. **The write is untouched**: the animation is not on the request path, it rides alongside it. `row_dismiss_controller` starts the motion on the `submit` event and then *pauses Turbo's render* — `turbo:before-render` is preventable and resumable, so the visit the button kicked off waits on the animation rather than the animation racing the network. On any real connection the response is the slower half and the send-off is free; on a fast one the render is held ~400ms, which is the point. Three things keep that hold honest: a safety timer resumes the render regardless, so a transition that never ends can never freeze a page mid-visit; a failed write (`turbo:submit-end` without success) puts the row back rather than leaving a phantom hole; and the inline height the collapse needs is cleared in the same task as `resume()`, because the app morphs on redirect-to-self and morph matches these rows by position — a leftover `height: 0` would otherwise land on whichever row moved up into its place. Nothing opts out of the app-wide reduced-motion floor: asked for less motion, the row goes the instant it is tapped, which is exactly what this screen did before. — *Built: the `row-dismiss` Stimulus controller and the `.row-leaving`/`.row-gone`/`.btn-chosen` atoms, wired from `tasks/_task` wherever the row offers the reschedule pair. It is a general shape, not a task feature: any row whose own button takes it off the list it is in can carry it.*
