**D-provider-presets. A provider preset may carry quirks, not just a URL — but only quirks the one adapter can absorb.**
Anthropic and Google both publish OpenAI-compatible chat-completions endpoints that take a plain API key on the `Authorization` header, so "add Claude" and "add Gemini" are a `base_url` and a label — exactly the shape D10 predicted, and the reason neither needs a vendor gem, an SDK, or a second code path. What they *did* need is the admission that a preset is more than a URL: Anthropic's compatibility layer documents `response_format` as **ignored**, and this app asks for JSON on nearly every call (`json: true` — every categorizer, every tool, every analyzer), so a URL-only preset would have shipped a provider that silently returns prose where the app expects a Hash. The fix stays inside the adapter as two optional preset keys — `json_mode: :prompt`, which appends the JSON instruction to the last user turn instead of setting the field, and `max_tokens:`, which sends the output cap Anthropic's underlying Messages API wants on every request. The instruction goes on the **last user message**, not a system message, because Anthropic hoists and concatenates every system message to the front of the conversation, which is the worst place for a formatting rule; and the client's existing fence/prose salvage (D-llm-errors) is the second net under it. The boundary this sets for the next provider: a preset may declare *how* to ask for something the adapter already does, and may not introduce a request shape, an auth scheme, or a response shape of its own. A provider that needs those is a `custom` endpoint behind somebody's proxy, or it isn't OpenAI-compatible and doesn't belong in the picker. — *Built: `ModelProfile::PROVIDERS` gains `anthropic` and `google`; `Llm::Client` gains `json_mode:` and `max_tokens:`.*
