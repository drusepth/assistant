**D-purge-by-diff. The reset finds its attachments by diffing, never by listing them.**
`Admin::HouseholdReset` promises that the storage panel reads zero the moment the redirect lands (D-household-reset): Active Storage cascades as `purge_later`, which is fine for one deleted document and wrong for a reset that claims a clean instance. It kept that promise with a hand-written list of model names — banner, documents, photos, export archive — and **a hand-written list of every attachment in the app is a list that goes stale.** By the time pets arrived it had already missed recipe images and every avatar (member, contact, and now pet): four kinds out of eight, added by three separate branches, none of which had any reason to know this file existed. The bug it produced was small and quiet, which is why it survived — on a single-household box, the case the button exists for, `clear_instance_leftovers`' unattached sweep caught the strays anyway, so the promise held *by accident*; on a multi-household instance the blobs and their bytes simply sat there until the cascade's jobs ran.

The replacement keeps no list at all: note which blob ids are attached *before* the destroy, and purge whatever stopped being attached *after* it. A blob that was attached and now isn't was detached by this destroy — there are no model names anywhere, so nothing can fall out of step, and the next `has_one_attached` anyone adds is covered before it is written. It is also strictly safer than the list it replaces, which is the part worth keeping: another household's files are still attached afterwards and so are never in the difference, and a direct-upload blob sitting unattached while somebody fills in a form was never in the "before" set — so an upload in flight elsewhere on the box survives. That last case is exactly the trap the instance-wide unattached sweep has to gate itself behind ("only when the last household is gone"), and the reason it could never have been promoted into the general answer. The regression test attaches one of *everything* and asserts both the row and the bytes are gone; a kind it forgets is still purged, because the mechanism never learned any names. — *Built 2026-08 alongside the pets wave, which was the fourth attachment kind the old list would have missed.*
