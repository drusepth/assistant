**D-household-reset. Owning your data includes throwing it away: /admin can empty the household back to the signup form.**
A self-hosted instance is also its own staging environment — there is no `db:reset` on a box you reach through a browser, and the fastest way to see onboarding a second time is to be a new instance again — so trying the app out otherwise leaves permanent debris. `/admin` gains a reset that destroys the household whole: every member account, every item they own, every uploaded file (purged inline, not `purge_later`, so the storage panel is honest immediately), and the user-created lenses and error log that sit *outside* household scope — those last two only when the wiped household was the last one on the instance, since sections have no `household_id`. The confirmation is a **typed word, not a dialog**: a click-through is muscle memory by the third reset. It deliberately takes the admin's own account too — landing back on the first-run form is the entire point — which makes it the one action in the app where an admin destroys another member's private items, so it stays admin-gated, logged, and paired in the copy with Settings → Export, the other end of the same ownership claim (D9's flag is a household role, not a master key, and this is the single sanctioned exception — it reads nothing, it only deletes). Not built: a keep-my-account "clear items only" variant, and any environment gate — self-hosters run their instance in production mode, and gating the button there would hide it from exactly the person it's for. — *Built.*
