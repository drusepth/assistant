**D-agent-prepared-work. Active means the agent arrives with the work already done — and still lands none of it until the click.**
The suggest-and-apply pipeline and the tool pipeline already meet at one seam: a watcher's `tool` action payload is a tool invocation the user hasn't clicked yet. Preparation is the agent submitting that form on its own dime during the scan and parking the result on the suggestion (`suggestions.tool_run_id`), so accept opens a finished draft instead of an empty form. Same tool class, same prompt, same `visible_to`-walled context — the only new machinery is a run mode where the `Tool::Base` landing helpers write **landing intents** into `tool_runs.output["landings"]` instead of rows (`origin: "agent"`, status `prepared`); the review page's Save click replays them (`land!`), which is the D20 accept, materially identical to the user having run the tool themselves. Preparable = a `:draft`-kind tool whose required inputs are fully prefilled (derived, deterministic; classes may opt out); plan and chat tools are not, in v1. Gates, because this is the first agent feature spending model tokens without a click: Active-dial sections only, a `users.prepare_work` toggle (default on — Active is already opt-in), newly-proposed suggestions only, and a hard `PREPARE_BUDGET` per user per scan — with a Settings transparency line counting scans and prepared drafts. Failure or no model degrades silently to today's prefilled redirect; a retired suggestion (D-suggestion-lifecycle) discards its prepared run with it, so a draft never outlives the nudge that occasioned it. Design in `docs/AGENT_PLAN.md` §2/§4. — *Planned (wave A2); not started.*
