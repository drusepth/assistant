**D-trip-spine. Trip grows from photo souvenir to the spine of the travel tool: planned trips, stays, legs, and one booked/planned bit.**
The original Trip (D-travel-facet) was a keepsake — a name, a date range and a box derived from photos after the fact. The requesting household lives the other way around: digital nomads in a new state every two months, whose actual daily question is "where will we be, is the next place booked, is the drive covered". So Trip becomes the spine both directions in time. A trip can now be **planned ahead** — a typed name, place label and dates, with the map box nullable (all-or-none validated, still only ever computed server-side from the owner's photos; `placed?` gates every photo-derived feature) — and it owns two new children. A **Stay** is where you sleep: location, kind (Airbnb/hotel/…), check-in/check-out, and `booking_status` — the one bit the whole tool tracks. Nights are half-open (check-out day belongs to the next place), so back-to-back stays chain with no phantom gap and `lodging_gaps` can honestly name the uncovered nights. A **TripLeg** is how you move: flight/drive/train/car-rental, date (+ optional return date for rentals and timed departure for flights), same booking bit — except a `drive` in your own car, which is bookless by default so the hub never nags about it (flip it to planned the year you start renting). Stays and legs belong to the *trip*, not a user — the itinerary is the thing the household edits together (D-trip-companions) — and `Trip#timeline` merges them chronologically, legs before stays on a shared day, because you fly in before you check in. The forward surfaces read fresh per request in the CareRadar idiom: `Travel::Outlook` computes the current stay, the next moves across every active trip, and the warnings (anything unbooked or uncovered inside a 45-day booking lead), the hub's "Where you'll be" card renders it, and the calendar gains a per-day stay band so the month answers the question at a glance. Events during a trip still derive from dates alone — which is exactly how "the thing you'll need to fly back for" surfaces on a trip page with no link table, keeping Q17 deferred. See `docs/TRIPS_PLAN.md`.
