**D-local-first-models. Cloud models are a checkbox you can uncheck, and the UI argues for the local answer before it offers them.**
The mission says the memory layer is the durable asset and models are swappable commodities — but every provider in the picker today is somebody else's computer, metered per token, and a household that never thinks about it has quietly rented the one part of the stack that sees all their documents. So `model_profiles.allow_cloud_models` (boolean, **default true**): unticking it takes every `cloud: true` preset out of the picker, a model validation refuses to save the pair, and `#client` raises rather than call a provider the household has said no to. Three things this deliberately is *not*. It is **not a firewall** — the self-hosted preset is free text, so someone can uncheck the box and type OpenAI's URL, and the copy says exactly that instead of implying a guarantee we can't make. It is **not the default** — shipping cloud-off with no local support yet would hand a new household an assistant that does nothing, and D9's rule is that the user makes this choice visibly, not that we make it for them. And it is **not a promise about today** — local models already work through the self-hosted endpoint (Ollama, llama.cpp and LM Studio all speak this wire format), so the picker's "Runs where you put it" group is honest now; what's missing is one-click setup, and the copy says *that* rather than pretending the group is empty. The argument in the callout is the point of the feature: your data stays yours, nobody logs your prompts, an assistant you rent can be repriced or switched off and one you run cannot, and no per-token bill means thinking harder about your own life never costs more. Shape-wise the gate reads a preset key (`cloud: true`), not a hardcoded list, so a first-class `ollama` preset lands later by simply omitting it. — *Built: the toggle, the grouped picker, the `.callout` atom, and the `provider-fields` gating.*
