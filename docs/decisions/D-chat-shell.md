**D-chat-shell. The chat surface has two layouts — `screen` and `panel` — and on a phone it is always `screen`.**
The D29 partial has two hosts that want opposite things: a dedicated conversation page should own the viewport (one scroller, composer welded to the bottom, chrome cut to a compact bar), while the panel embedded in a task page (D30) is a card in a flowing document and must stay one. Today it is neither — a `max-h-[calc(100dvh-20rem)]` scroller inside a card inside the scrolling page, which is two nested scrollers, a magic number that is wrong on every device, and a composer whose position depends on scroll state. So `_chat.html.erb` takes a `layout:` local (`:screen`/`:panel`, defaulting to the constrained case) and the height rules live in `.chat-screen`/`.chat-panel` atoms beside the existing chat set, not in per-view utilities. The corollary is the load-bearing half: **an embedded chat panel is never good on a phone**, because a card that is itself a scroller inside a scrolling page is precisely the bug — so below `sm` the task page's panel collapses to an entry point that opens the conversation full-screen (`GET /tasks/:id/conversation`, rendering with a possibly-nil run exactly as the panel already does), and stays inline from `sm` up. Chrome folds with it: below `lg` a `:screen` chat gets a compact bar (back, title, overflow menu) holding New session, Delete, and Save a recap, instead of a page header plus a three-line recap footer competing with the composer for the bottom of a phone. Full design in `CHAT_PLAN.md`. — *Built, with one correction: the viewport arithmetic lives on `.chat-page` (viewport − `--app-header-h` − `--keyboard-inset`) and `.chat-screen` is `flex-1 min-h-0` inside it, which is what lets a desktop page header sit above the screen without pushing it out. The layout's `min-h-screen` also had to go for a bleed page — it stacks a full viewport under the mobile header, so the document scrolled by exactly the header's height, which is the second scroller this decision exists to remove. The planned `chat-scroll` sentinel rewrite was dropped as wrong: an IntersectionObserver can't tell "the reader scrolled away" from "content grew below them", which is the only thing the `autoScrolling` flag is for.*
