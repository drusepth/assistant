**Q-intake-stated-due. Should a due date a document states beat the registry interval on the care radar?**
The care radar derives "due" as `last visit + kind.interval` (D-pet-care-radar), and its "booked" state is any future event of that kind. A vet's discharge sheet often states the next due date outright — "rabies: due 2029-08-12" for a three-year vaccine — which is better information than the registry's twelve months, but a future event carrying `care_kind: pet_vaccinations` would read as *booked*, which it isn't. Intake (D-document-intake) therefore lands stated due dates as `care_kind: none` future events: the calendar and the renewal radar give lead time, the care radar stays honest, and the registry interval stays the radar's only source. The real answer is probably a third input to `Health::CareRadar::Status` — a *stated due* beside last and next, read from events flagged as due dates rather than visits — but it changes a shared file for a case that intake is the first to produce, so it waits for the review page to show how often a stated date actually disagrees with the interval. — *Open; parked with INTAKE_PLAN §9.*
