**D26. Outside accounts link per-user with scope dials that default to everything.**
`linked_accounts` (one row per user per provider) is the layer that connects the services a user already lives in — email (IMAP), address book (CardDAV), calendar (CalDAV), Facebook, LinkedIn — so the assistant can eventually draw on them. Providers are first-party registry entries in `LinkedAccount::PROVIDERS` (D11: adding a service = one entry declaring label, credential fields, scopes). Access is scope-gated per link and **defaults to full access**: linking is consent, and we store only the scopes the user switched *off* (`disabled_scopes`), so a scope added to a provider later is granted to existing links without backfill — the same enabled-unless-disabled convention as section toggles (D4). The dials are visible, user-controlled configuration on the Settings page (D9: no hidden defaults), and consumers must read through `allows?`, which fails closed on unknown scopes. Credentials are a plaintext JSON blob for now; Milestone 4's AR-encryption setup (which now covers `model_profiles.api_key`) is the obvious vehicle — encrypting `linked_accounts.credentials` with it is a pending follow-up. Per-provider sync jobs/importers/tools come per demand, each honoring the link's scopes. The first two consumers are built on a shared `Dav::Client` (plain Net::HTTP, RFC 6352/4791 discovery with `/.well-known` fallback, or a pasted collection URL directly): `People::CarddavSync` pulls vCards through `People::Import`, and `Events::CaldavSync` pulls iCalendar payloads through `Events::Import` (its REPORT carries a time-range filter matching the Ics importer's 1-month-back/12-ahead window, so servers don't ship decades of history) — the same normalize/dedupe paths as file uploads, so sync and upload can never disagree. Both run read-only, gated on the link's "read" scope via `allows?` inside the service (not just the UI); providers with a consumer name it in the registry (`sync_service:`), and one `SyncLinkedAccountJob` dispatches through that, firing on link and from a "Sync now" button, recording `synced_at`/`sync_error` on the link for the Settings card. — *Built (linking UI, scope dials, registry, contacts + calendar sync). Remaining: credentials encryption, the email consumer, recurring background sync, and OAuth (see D27).*
