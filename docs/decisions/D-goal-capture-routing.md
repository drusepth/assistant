**D-goal-capture-routing. The one capture box stays, but the model routes: day-sized input files as a plain Task, not a Goal. (Amends D17.)**
D17's box always created a Goal, so "buy cat litter" became a goal card with a progress bar — permanent noise in exactly the planning surface D-tasks-two-surfaces builds. The box keeps its promise (type what you want to accomplish, never pre-categorize), and the breakdown call now renders one more verdict, `kind`: goal-sized input becomes a Goal plus plan exactly as before; **day-sized input becomes a single dated, section-tagged Task with no goal ceremony** — the placeholder Goal row is deleted and the task takes its place. Routing applies only to **bare captures**: a non-append run on a goal with no steps, no description, no hand-set sections, and no target date. Anyone who filled in the full goal form made the choice themselves, and that choice is never second-guessed (D16). Because capture now lands on the goal page (D-tasks-two-surfaces), a conversion announces itself there — the planning container is stream-replaced with "this was day-sized, so it went straight to your board" and the task's row — rather than teleporting the user somewhere unexplained. With no model configured nothing routes and every capture stays a Goal, per D-no-keyword-logic: the feature is off, not approximated with keywords. Two explicit inputs (a goal box and a task box side by side) were rejected as reintroducing the pre-categorization burden the one box exists to remove.
