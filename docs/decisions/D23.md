**D23. Silence is a product feature and an operations bug: swallowed failures get logged to `app_errors` and surfaced at `/admin`.**
Best-effort AI work deliberately hides its failures from the person who triggered it (D16) — a model that times out leaves a task unsorted rather than showing a stack trace. That is right for the user and wrong for whoever runs the box, who otherwise never learns the model has been down for a week. Every `rescue` that swallows now also calls `AppError.record` (source, error class, message, backtrace, actor, context ids); `record` rescues itself, because logging a failure must never cause one. An `ApplicationJob` safety net extends this to errors nobody rescued — an unhandled job error is still invisible from the operator's chair, so it gets recorded (best-effort user attribution from the job's arguments) before re-raising to the backend, while a record deleted before its job ran discards quietly instead of posing as a failure. Every error at `/admin` — `app_errors` rows and Solid Queue failures alike — carries a paste-ready plain-text report behind Copy / Copy all buttons, so "what broke" can be handed whole to a bug report or an AI chat. The table is a 500-row ring buffer — an unattended self-hosted instance shouldn't grow it forever.
`/admin` (household admins per D15, not a hardcoded user id) shows model-profile status, job-backend status, and the log. It reports **counts, never contents**, for other members' failed runs and documents: the admin flag is a household role, not a master key, and items stay private until shared (D9). Solid Queue is production-only here, so its panel degrades to an explanatory note rather than crashing in development. — *Provisional until the M3 watcher pass, which may want to read this table.*
